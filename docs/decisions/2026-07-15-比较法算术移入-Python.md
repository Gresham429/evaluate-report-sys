# ADR-001：比较法算术移入 Python，Excel 降级为知识源

- 日期：2026-07-15
- 状态：**已采纳**
- 决策人：用户
- 影响范围：头号铁律 C1、`src/extractor/`、新增计算引擎、实例库、钉钉集成的可行性

## 背景

立项时（见 `docs/superpowers/specs/2026-07-15-房地产估价报告生成系统-design.md` 第 2 节）用户明确要求：

> **C1 只读不改**：Excel 的公式与知识是既定正确的，系统只读不算。

整个系统据此建成：`openpyxl` 以 `data_only=True` 只读缓存值，一个数都不重算，也不回写。

2026-07-15 用户提出新需求：

> 比较法的三个实例要**动态选择**，维护一个按年份与类别分类的**实例库**，每次生成报告时人工挑选三个。

## 冲突

换实例必然触发重算：

```
换掉实例A
  → 该实例 28 个因素档次全变
  → M 列 30 个指数重算（INDEX/MATCH 查基础表 × 修正系数）
  → 比准价格 T37（30 项连乘）重算
  → 评估结果 T39（加权平均）、离散度 X37 重算
```

「动态选实例」与「只读不算」在逻辑上不可兼容。

## 关键实证

### 一、写回 Excel 会清空其全部计算结果

用 `openpyxl` 改写实例A（`E3`/`E4`）并保存后实测：

```
改之前:  T37 = 2.92    T39 = 2.83
改之后:  T37 = None    T39 = None
```

`openpyxl` 只写公式、不算公式，保存时丢弃全部缓存值。**这不是 bug，是固有行为。** 要恢复结果必须由人打开 Excel/WPS，或安装 LibreOffice（约 1GB，违背绿色 exe 目标，且与跨平台约束 C7 的初衷相悖）。

结论：**「软件改 Excel 再读结果」这条路不通。**

### 二、Python 引擎可精确复现 Excel

约 40 行实现，基础表知识仍从 Excel 读，三份真实 Excel 的 12 个数字全部精确复现：

| | Excel 比准价格 | Python 比准价格 | Excel 评估结果 | Python 评估结果 |
|---|---|---|---|---|
| 农用 | 1410 / 1393.89 / 1393.89 | 相同 | 1399.26 | 1399.26 ✅ |
| 办公 | 2.92 / 2.77 / 2.80 | 相同 | 2.83 | 2.83 ✅ |
| 商业 | 3.15 / 3.40 / 3.40 | 相同 | 3.32 | 3.32 ✅ |

### 三、三个实例互不依赖

公式列引用实测：`T37=[L,M,T]`、`U37=[L,N,U]`、`V37=[L,O,V]`。三条链独立，仅在 `T39`（加权）与 `X37`（离散度）汇合。实例是自包含记录，可自由替换——这是实例库成立的技术前提。

## 决策

**采纳方案甲：系统自行执行比较法算术。** C1 改写为：

> **新 C1**：Excel **基础表的知识**（28 个比较因素、每因素 5 档描述、每差 1 档修正系数、分值标尺 2/1/0/-1/-2）是既定正确的，系统只读不改；**比较法的算术由系统执行**，且必须精确复现三份金样的 12 个数字。
>
> `实勘表` 的取值语义仍严格只读（原 C1 于此处不变）。

### 边界：什么留在 Excel，什么进 Python

| | 内容 | 位置 | 会变吗 |
|---|---|---|---|
| **知识** | 28 个因素是哪些；每因素 5 档怎么描述；每差 1 档的修正系数；分值标尺 2/1/0/-1/-2 | **Excel 基础表，运行时读** | 会 —— 改 Excel 即生效，Python 不动 |
| **算术** | `指数=(实例分−对象分)×系数+100`；`比准价=成交价×∏(100/指数)`；`评估结果=Σ(比准价×权重)` | Python | 不会 —— 《房地产估价规范》定死 |

**这是本决策的核心**：被"重实现"的只有三行永不改变的算术；用户真正会调整的知识仍在 Excel 里。

## 后果

**得到**
- 界面选实例 → 数字立即重算，实例库有了意义
- 不再需要「改完 Excel 必须先保存」这条约束
- 钉钉自动化（远程填表 → 拉取 → 算 → 出报告 → 回传）成为可能

**失去 / 风险**
- **Excel 不再是计算引擎**。用户改 Excel 里的**公式**对系统不再有任何效果——只有改**基础表数据**才生效。此点须在用户文档中显著说明。
- 双实现漂移风险。**缓解**：基础表仍从 Excel 读；三份金样的 12 个数字写成回归测试锁死，算歪即红。
- **市场状况调整指数**（比较法第 8 行，实测办公为 98/95/95）是手填常数、非公式，且**不属于实例固有属性**——它是「实例成交日期 × 本项目价值时点」的配对属性。实例库存不了它，界面上须让估价师为每个选中的实例现填。

## 未决

- 实例库是否为每条实例保留「市场状况判断依据」备注字段（现有 Excel 里 98/95/95 这类判断无任何依据记录，该知识正在散失）
- 三个权重现各写死 1/3，是否需要按项目可调
