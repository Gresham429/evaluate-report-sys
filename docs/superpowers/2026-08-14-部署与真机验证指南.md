# 部署与真机验证指南（2026-08-14 本轮四特性）

本轮在 `main`（本地未 push）实现了四个特性，须一并部署 + 真机验证：

| 特性 | 面 | 部署动作 |
|---|---|---|
| #1 拉取草稿去重 | 办公端 | 仅重启/重打 exe |
| #3 双向同步（回写+3-way 合并+冲突页） | 办公端 + broker + 小程序 | broker 重部署 + 小程序重传 |
| #2 选共有人（owners 并集） | broker + 小程序 | broker 重部署 + 小程序重传 |
| #4 组织架构上级（默认关） | 办公端 | env 开关 + 端点校准 |

三个部署面：**A. broker（阿里云 FC）** / **B. 小程序（钉钉）** / **C. 办公端（本机/exe）**。

---

## 步骤 0：前置确认（5 分钟）

1. 仓库根 `.env`（gitignored）凭据齐：`YIDA_APP_KEY`/`YIDA_APP_SECRET`、`NOTABLE_BASE_ID`、
   `NOTABLE_OPERATOR_ID`、`NOTABLE_SURVEY_SHEET`、`AMAP_KEY`、`OFFICE_OPERATOR_ID`、`OFFICE_ADMINS`。
2. broker 部署包是最新的：`serverless/dist/survey_broker_fc.zip`（应含 13 个文件，含 `merge.py`）。
   不确定就重打：`uv run python serverless/package.py`。

---

## 步骤 1：部署 broker 到阿里云函数计算（FC）

> 这版最全：listSurveys + 已定稿锁定 + owners + **3-way 合并** + **owners 并集** + load 回 owners。
> 覆盖你之前部署的所有版本。

1. 登录阿里云 FC 控制台，进你的 survey_broker 函数。
2. **上传代码**：`serverless/dist/survey_broker_fc.zip`。
3. **运行方式**（自定义运行时 · Web Server 模式）：启动命令 `python3 -m serverless.survey_broker.server`，监听端口 `9000`。
4. **环境变量**（不变则不用动，见 `serverless/survey_broker/README.md`）：
   `DINGTALK_APP_KEY`、`DINGTALK_APP_SECRET`、`NOTABLE_BASE_ID`、`NOTABLE_OPERATOR_ID`、
   `NOTABLE_SURVEY_SHEET`、`AMAP_KEY`。
5. **冒烟**（部署后立刻）：对函数 URL POST 一个 `{"action":"whoami","payload":{"authCode":"<真机取的code>"}}`，
   或从小程序体验版点一次「暂存」，确认 200、多维表里出现/更新一行。
   ⚠️ 若报 `ModuleNotFoundError` → zip 缺文件（见 memory「broker打包清单硬编码」），重打再传。

## 步骤 2：重传小程序（钉钉开发者工具）

1. 用钉钉开发者工具打开 `miniprogram/`。
2. **校准选人 API**（#2 的唯一待校准点）：打开 `pages/form/form.js` 的 `onPickOwners()`——
   里面列了候选 `dd.chooseInteriorContacts` / `dd.complexChoose` / `dd.chooseContact`。
   真机里试出可用的那个，确认它的回执字段（`userid`/`name`），必要时调整 `_addOwners` 的取值映射
   （`p.userid || p.userId || p.emplId || p.id`、`p.name || p.userName`）。
3. 上传新版本、设为体验版（含新增 `pages/conflict/` 冲突页 + 表单共有人区）。

## 步骤 3：办公端（本机 / exe）

1. 用最新 `main` 代码：`uv run python -m src`（或重打 exe，见根 README「打包」）。
   —— #1 拉取去重、#3 办公端回写「保存回问卷」+ 冲突弹窗 直接生效，无需服务端部署。
2. **#4 组织架构上级（可选，默认关）**：先跑通「上级可见/可定稿」须先真机校准 org 三个 topapi 端点
   （`src/dingtalk/org.py` 里标了 `# 待真机校准`：`user/get.leader_in_dept`、`department/listsub`、
   `user/listid`）。校准通后，在 `.env` 设 `组织架构上级=on` 才启用；**不设=保持现状（只有管理员能定稿）**。

## 步骤 4：真机验证清单（逐项勾）

**#1 拉取草稿去重（办公端）**
- [ ] 「从实勘问卷拉取」同一问卷两次 → 第二次提示「已有草稿，已为你续上」、草稿数不增。

**#3 双向同步**
- [ ] 办公端拉一份「已提交」问卷 → 出报告页出现「保存回问卷」按钮。
- [ ] 办公端改字段 A「保存回问卷」；另一处（手机/另一办公）改字段 B → 再保存 → 两处都在（自动合并）。
- [ ] 双方改**同一字段** → 办公端弹**冲突弹窗**逐字段选；手机端弹**冲突页**逐字段选 → 保存成功。

**#2 选共有人**
- [ ] 手机填问卷时「从通讯录选共有人」→ 选一个人 → 提交。
- [ ] 该共有人在**他自己**的办公端「出报告」列表能看到这份问卷（可见性生效）。
- [ ] 甲设备加共有人 X、乙设备加共有人 Y（同一问卷）→ 最终共有人含 X 和 Y（并集，谁都不丢）。
- [ ] 填报人一栏标「（填报人）」且无删除按钮（不可删）。

**#4 组织架构上级（仅当已设 `组织架构上级=on`）**
- [ ] 部门主管办公端能看到 / 能定稿其下属填报的问卷；非上级看不到。

**回归（本轮没动但同属问卷流，一并点）**
- [ ] 审核全流程（发起审核 → 审核通过 → 已定稿只读）。
- [ ] 办公端钉钉扫码登录、只看自己。
- [ ] 离线出报告 → 联网对账同步定稿。
- [ ] 五/六轮 UI（逐因素描述、权重、系数偏离、新四类下拉、两份下载）。

## 出问题时

- broker 报错 → 看 FC 日志；`ModuleNotFoundError` = 打包漏文件。
- 小程序选人无反应 → 选人 API 名不对（步骤 2.2 换候选）。
- 办公端「保存回问卷」401/404 → 检查登录态 / `OFFICE_OPERATOR_ID`（须与填报人同源 userid）。
- 冲突老是弹 → 正常（同字段真被两边改了）；选一次即收敛。
