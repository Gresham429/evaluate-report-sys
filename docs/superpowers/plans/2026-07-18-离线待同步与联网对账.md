# 离线待同步草稿 + 联网对账 + 报告编号统一发号 —— 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 app 在联网（`承载后端=多维表`）时点「出报告」自动向多维表领全公司唯一号并出正式报告；断网时点「出报告」存成「待同步」草稿；联网后在草稿列表逐条 [同步定稿] 或 [删除]。

**Architecture:** 整套改动**加在多维表模式之上、对本地模式零影响**（沿用工厂「默认关＝行为一字不变」的既有原则）。三态由前端在点「出报告」时先探 `GET /api/online` 决定：`local` 模式照今天渲染（估价师手填编号）、`notable+online` 走 `/api/render` 由后端领号、`notable+offline` 存待同步草稿。领号复用**已真机验通**的 `draw_report_number`（往台账表插一行拿 autoNumber），报告编号**照旧显式存进台账快照**——replay 不读它，故快照自洽（铁律 #5）不受影响。

**Tech Stack:** Python 3 / FastAPI / dataclass(frozen) / 单文件原生 JS 前端 / pytest + fastapi.testclient / 多维表 REST（钉钉 notable，仅经注入 transport 单测，不触网）。

## Global Constraints

逐条从铁律（`docs/README.md` §2）与本轮 spec（`docs/superpowers/specs/2026-07-18-离线待同步与联网对账-design.md`）抄来，**每个任务都默认受这些约束**：

- **台账只增不改（铁律 #4）**：`LedgerStore` 无 remove/save/update；`NotableLedgerBackend` 无 update/delete。领号与同步都只能 append。**任何"回填/改写已写行"的方案都违约，禁用。**
- **快照自洽（铁律 #5）**：一条台账离开库能独立 replay。`replay()` 用 `基础表/档次/实例/方法/权重` 重算，**不读 `报告编号`**——故报告编号怎么存都不影响 replay。
- **运行时零 AI（铁律 #3）**：领号、在线检测都不是"报告生成阶段的模型调用"，保持零模型。
- **本地模式行为一字不变**：`承载后端` 未设＝走本地文件后端，今天的 525 项测试全在本地模式跑，**不许因本轮改动变红**。新增能力一律 gate 在 `config.use_notable()` 之后。
- **改 UI 必须真机点（铁律 / §5 坑 2、4）**：前端是单文件原生 JS，单元测试拦不住 UI。前端任务的验收是真人浏览器走一遍，不是"绿了就行"。
- **中文不做 HTTP 路径参数（§5 坑 4）**：新端点 `/api/online` 无路径参数，天然规避；沿用现有 `{record_id}`/`{draft_id}` ASCII 参数约定。
- **.env 真值不得泄进单测**：`config.py` 刻意不自动 load .env。**只在 `__main__.main()`（真运行入口）load**，`create_app()` 与测试永不 load——否则测试会拿真凭据打真钉钉。
- **报告编号格式**：`正恒评报字[YYYY]第{N}号`，由 `src/dingtalk/report_number.py::draw_report_number` 唯一产出，勿另写一份。

## 关键设计决策（spec §11 交实施计划敲定的四件，此处对着代码定死）

### 决策 A：报告编号 ↔ 台账行模型 —— **复用现有领号 + 编号显式存快照（不派生、不回填）**

**问题**：多维表 autoNumber 在"插入一行"时才生成，而 `报告编号` 又要在 render **之前**拿到（要印进 docx）；同时铁律 #4 禁止改写已写行。三者叠加使"编号存进本行快照且等于本行 autoNumber"在单次 append 内**物理上不可能**（autoNumber 插入后才有值，要写进同一行的快照就得二次 update＝违约）。

**选定方案（Option B）**：
- 领号：**复用 `draw_report_number()`**（现状已真机验通）——它往台账表**插一条极轻的领号行**（`快照` 字段留空），回读该行 autoNumber `报告序号`＝N，组装 `正恒评报字[YYYY]第N号`。
- 出报告：把 N 注入 `Project.report_no` → render → 照旧 `LedgerStore.append(entry)` 写**正式台账行**，`报告编号=N` **显式存进快照**（就是 `LedgerEntry.报告编号` 今天的存法）。
- replay 自洽：replay 不读 `报告编号`，故此方案对铁律 #5 **零影响**。
- 本地模式：无多维表、无 autoNumber → **不领号**，`报告编号` 照旧取表单手填值（今天的行为）。编号"派生 vs 存快照"在本地模式没有 autoNumber 可派生，只能存——两模式统一为"存"，读路径无需任何派生逻辑。

**代价（需你在评审时点头，可否决）**：
1. 每出一份正式报告，台账表多一条**领号占位行**（`快照` 空 → `iter_payloads` 天然跳过，不污染台账读取、不进 replay、不进列表）。
2. `报告编号` 的序号**会跳号**（领号行吃 N、正式行吃 N+1，下一次领号从 N+2 起）。

这两点 spec 已明确接受：`report_number.py` docstring「行创建即自增、允许跳号——正合"领了没出报告即跳空"」。**若你不接受占位行堆在公司共享表里**，备选是 Option E（单行、读时从 autoNumber 派生编号），代价是要改领号流程 + 给 append 加"回读 autoNumber" + `NotableLedgerBackend.iter_payloads` 读时派生编号 + 处理本地后端无 autoNumber 的落差——surface 更大、且让 `报告编号` 不再是快照里的权威字段。**本计划锁 Option B（复用已验通代码、最小 diff、读路径无派生、#4 天然满足）。**

> 领号时机：`report_number.py` docstring 原写「实勘开始」，本轮 spec §6 改为**点「出报告」且在线时**领号。以 spec 为准。

### 决策 B：本地 vs 多维表模式 —— **三态只在多维表模式生效，本地模式＝今天**（补 spec 未言明的边界）

spec §5「`承载后端≠多维表` → `{online:false}`」与 §3「`online:false` → 待同步草稿」若直译，会让**本地模式永远出不了报告**（永远 false → 永远待同步）。这会打断交付 exe（不带 .env → 本地模式）与全部本地测试。**resolution**：三态流程只管多维表模式；本地模式绕过在线/离线闸门，照今天渲染。故 `/api/online` 返回 `{online, mode}`，前端按 `mode` 分流：

| `mode` | `online` | 触发条件 | 「出报告」走向 |
|---|---|---|---|
| `local` | `false` | `承载后端≠多维表` | 照今天：`/api/render` 手填编号、本地台账。**不待同步** |
| `notable` | `true` | `承载后端=多维表` 且探测成功 | `/api/render`：后端领号→render→多维表台账 |
| `notable` | `false` | `承载后端=多维表` 但缺凭据/探测失败 | 存待同步草稿（`待同步=true`） |

后端 `/api/render` 做同样分流并兜防御：多维表模式但 client 缺失或领号抛错 → **HTTP 503**（前端据此转存待同步），绝不出无号报告。

### 决策 C：在线检测 —— **`list_sheets()` 轻探 + 短超时 5s**

`GET /api/online`：`use_notable()` 假 → `{online:false, mode:"local"}`；真则 `config.build_client(timeout=5.0)`，client 为 None → `{online:false, mode:"notable"}`，否则 `client.online()`（内部 `list_sheets()` 成功＝True、抛错/超时＝False）。现 `_urllib_transport` 硬编码 30s，本轮把超时做成 `NotableClient` 可配参数（默认仍 30s，探测走 5s），免离线时「出报告」卡半分钟。

### 决策 D：.env 加载时机 —— **仅 `__main__.main()`，从 `app_dir()/.env`**

新增 `src/__main__.py::_load_dotenv()`（照 `tools/dingtalk_whoami.py` 的 `setdefault` 写法），在 `create_app()` 之前调。位置 `app_dir()/.env`：冻结时 exe 旁、开发时仓库根（`paths.py::app_dir()`）。**不进 `create_app()`**（测试走 `create_app()`，一旦 load 就会把真凭据灌进单测）。

```python
def _make_urllib_transport(timeout: float) -> Transport:
    """按超时秒数生成真实 transport：只访问固定的钉钉域名。"""
    def _transport(
        method: str, url: str, headers: dict[str, str], body: bytes | None
    ) -> tuple[int, str]:
        req = urllib.request.Request(url, data=body, method=method)
        for key, val in headers.items():
            req.add_header(key, val)
        try:
            with urllib.request.urlopen(req, timeout=timeout) as resp:  # noqa: S310  仅钉钉域名
                return resp.status, resp.read().decode("utf-8")
        except urllib.error.HTTPError as exc:
            return exc.code, exc.read().decode("utf-8", "replace")
        except urllib.error.URLError as exc:
            return 0, f"网络错误：{exc}"
    return _transport
```

```python
def _load_dotenv() -> None:
    """把 exe/仓库根旁的 .env 灌进环境变量（钉钉凭据、承载后端开关）。

    只在真运行入口调，**不进 create_app()**：测试走 create_app()，一旦在那 load
    就会把真凭据带进单测、去打真钉钉（config.py 的注释也是这个立场）。
    setdefault 语义：命令行/CI 已显式设的变量优先，.env 只补缺。
    """
    env_file = app_dir() / ".env"
    if not env_file.exists():
        return
    for line in env_file.read_text(encoding="utf-8").splitlines():
        line = line.strip()
        if not line or line.startswith("#") or "=" not in line:
            continue
        key, _, value = line.partition("=")
        os.environ.setdefault(key.strip(), value.strip())
    logger.info("已加载 .env：%s", env_file)
```

    _setup_logging()
