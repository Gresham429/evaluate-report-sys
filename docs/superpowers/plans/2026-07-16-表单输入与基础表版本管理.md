## 0. 本轮要解决什么

用户：「我们输入并不是 excel；而是 excel 里面自带流程需要的输入」。

实勘表这一层要从 Excel 换成表单。基础表撤不掉——它是估价知识本身（决策记录
§2.5），但它得从「每份报告传一次 Excel」变成「导入一次、存副本、按版本取用」。

```
现在   每出一份报告 → 传 1 个 Excel（实勘表 + 比较法 + 基础表 三合一）
之后   基础表      → 导入一次，存副本，改了重导（方案乙）
       实勘表      → 表单
       比较法实例  → 实例库（已有）+ 新增实例录入表单
```

## 3. T1：基础表存储与版本管理

### 3.1 版本号用内容指纹

决策记录 §3.3 定：内容指纹（哈希）当版本号，非人工填写。现有基础表**无任何
版本标记**（三份实测全无），人工填会忘、会填错、会复制粘贴时忘改。

**指纹的口径必须钉死**：把 `Knowledge`（因素名、各档次描述、每档分值、修正
系数、分值标尺）按固定顺序规范序列化后 SHA256 取前 12 位。

> ⚠ 决策记录 §3.3 记了三个指纹（农用 `56ce11aa5505`、办公 `6584dc9bf9d2`、
> 商业 `5df34ffb0b64`）。那是探索期临时脚本算的，**拼接口径未留存**，本轮
> 重定口径后数值大概率不同。**指纹的价值在「内容一变即变」，不在具体字符串**
> ——无人依赖那三个值。实测出新值后回填决策记录，不假装对得上。

### 3.2 文件布局

```
data/基础表/
  办公-{指纹}.json     ← 不可变。改系数重导 → 新指纹 → 新文件，旧的留着
  农用-{指纹}.json
  商业-{指纹}.json
  台账.json            ← 哪版、何时导入、从哪个文件导入
```

**旧版本永不覆盖**——「能复现」是可复查的前提（决策记录 §3.1）。

### 3.3 验收

- 三份真 Excel 各导出一份，指纹两两不同
- 同一份 Excel 导两次 → 指纹相同，不新增文件
- 存→取往返后 `Knowledge` 与直接从 Excel 读的完全相等（含 `row`，Excel 路径要用它定位比较法表行）
- 台账如实记录导入时间与来源文件名

## 4. T2：草稿存储

草稿是**表单状态的续填缓冲，不是权威数据**。故按不透明 JSON 存，后端不理解其
形状——表单字段日后必然增删，后端跟着改一次就是一次多余的耦合。

```json
{"id": "...", "报告编号": "...", "类别": "办公", "更新时间": "...", "数据": { ... }}
```

验收：存、列、取、删；列表按更新时间新→旧；`报告编号`/`类别` 抽出来做列表展示。

## 5. T3：输入抽象层（决策记录 §2.6）

`/api/extract`（读 Excel）与表单是**两条并行的输入路径，必须产出同一个
`Project`**。这正是[比较法引擎与实例库设计 §5](../specs/2026-07-16-比较法引擎与实例库-design.md)
提出、当时因 YAGNI（无第二实现）而缓做的抽象层。**现在有第二个实现了。**

比较法引擎真正需要的输入只有三样：

```
category        类别
knowledge       基础表知识    ← Excel 路径从上传件读；表单路径从 T1 的库里取
subject_levels  估价对象档次  ← Excel 路径从比较法表 D 列读；表单路径从 28 个下拉框收
```

重构 `compute_from_selection(path, ...)` → 按这三样收参，另留一个从 Excel 路径
构造它们的适配器。**引擎自此不认识 Excel。**

## 6. T5：表单界面

### 6.1 不拼凑（用户明确要求）

19 项基本字段**全部人工填，系统不拼凑**。曾建议自动拼 `project_name`、`scale`、
`work_period`、`scope`/`purpose`，可把人工填写降到 8-10 项，**用户否决：「不拼凑
实地勘察去填写」**。理由成立——拼凑出的文字进了报告是要签字的，责任不清。

### 6.2 但要替他核（决策记录 §2.3）

用既有校验器机制（**只提示、不阻断**）补一条：

```
scale 填「房屋建筑面积723.69平方米…」
一览表 356.29 + 367.4 = 723.69         ✅ 一致
若手滑打成 732.69
→ ⚠ 规模字段写的 732.69 平方米，与一览表面积合计 723.69 不符，请复核
```

**不替他填，但替他核。**

### 6.3 28 个下拉框

选项全部来自基础表（T1 的库），5 选 1，不是自由输入。档次一选，指数即可算。

## 7. 不做的

- **实例推荐**：不做。用户与 Claude 均无法验证可比性准则（决策记录 §7）
- **权重可调**：写死各 ⅓（用户决定）
- **报告里写明用了哪三条实例**：牵涉执业规范，须执业估价师定夺（决策记录 §8.5）
- **基础表旧版本的取用界面**：本轮只保证「存得住、取得回、看得见当前是哪版」。
  「取 v1 重算 2026-03 那份报告」的完整复现流程，等报告台账（决策记录 §3.3 的
  `生成台账.json`）一起做
