- 承接：ACL 判定器（`permissions.py` 的 `Viewer.subordinates` / `can_see` / `can_finalize`）已就绪，
  P1 里 `subordinates` 恒空（只有 admin 能定稿/看全部）。本轮把它接上钉钉部门树。

## 目标

`org.subordinates(U)` = U 主管的部门 + 其所有子孙部门的全体成员 userid（去掉 U 自己）。
接进 `session.viewer()` → owner 的上级即可见 owner 的问卷、可定稿。

## 设计（纯算法可测 + API 层 fail-closed 待校准）

- **纯计算** `_subordinates(userid, client)`：leader 部门 → 递归子孙部门（防环 visited）→ 各部门成员并集，去 U。
- **OrgClient(transport)**：三个钉钉接口，HTTP 注入、端点标「# 待真机校准」——
  `topapi/v2/user/get`(leader_in_dept)、`topapi/v2/department/listsub`(子部门)、`topapi/user/listid`(成员)。
- **subordinates(U)**：进程内缓存按 U 带 TTL（10 分钟）；未配置/网络/解析错 → **空集（fail-closed）**。
- **token**：复用 `config.build_client().access_token()`；`build_client()` 为 None（未配）→ 空集。
- **接线**：`session.viewer()` 的 `subordinates=frozenset()` 改为 `org.subordinates(current_operator())`。

## 安全性（可即上线）

端点未校准/未配置/出错时恒返回空集 → 行为**与 P1 完全一致**（只有 admin 能定稿/看全部）。
真机把三个端点校准通后，「上级可见/可定稿」自动生效，无需再改代码。

## 测试

- 纯算法：leader→子孙→成员并集 / 无 leader 部门 / 空 userid / 递归多层 / 自己不算下属 / 环防护。
- 缓存：TTL 内不重复打接口；过期重取。
- fail-closed：transport 抛错 → 空集；未配置 → 空集。
- 接线：`session.viewer()` 用 org 填 subordinates（monkeypatch org）。
