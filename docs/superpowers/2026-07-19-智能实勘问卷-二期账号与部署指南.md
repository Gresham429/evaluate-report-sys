# 智能实勘问卷 · 二期账号申请与部署操作指南

> 面向建设方（你）。一期（办公端拉取适配器）已实现并并入 main；二期要补上「谁往多维表写问卷」——
> 钉钉小程序（现场手机填）+ serverless broker（替小程序读写多维表、换 token）+ 高德（地图预填事实）。
> 本指南只讲**你要去哪、点什么、拿到什么给我**；代码（serverless + 小程序）账号就位后由我写。
> 注：各平台控制台菜单名可能随版本微调，以「找到对应功能」为准，链接给的是官方入口。

---

## 0. 先认清三样账号各管哪一段

```
现场手机（钉钉小程序）──调用──▶ serverless broker（阿里云函数计算）──┬─▶ 钉钉多维表「实勘问卷」表（已有，一期用的那套）
   估价师填表/拍照/看地图预填            持 AppSecret+高德Key、换token、读写多维表  └─▶ 高德 REST（逆地理/周边POI，只取事实）
                                                                        ▲
办公桌面端（现成，一期已通）──直读多维表「已提交」──拉取预填出报告──────┘
```

- **钉钉小程序**＝前端载体（估价师在钉钉工作台打开的那个页面）。
- **阿里云函数计算（FC）**＝serverless broker，唯一持密钥的地方（小程序前端不能塞 AppSecret，谁都能扒）。
- **高德**＝地图数据源（附近公交站/地铁/配套的**事实**，好中差档次仍估价师自己定）。
- 三样都跟**办公端无关**——办公端一期已经用现有 `.env` 那套凭据直读多维表，不碰小程序/serverless。

## 1. 钉钉小程序（前端载体）

**去哪**：钉钉开放平台 https://open-dev.dingtalk.com/ ，用**组织管理员**账号登录（组织＝杭州宜家房屋置换有限公司，与承载层那套同组织）。

**做什么**：
1. 「应用开发」→「小程序」→ 新建一个**企业内部**小程序（工作台小程序）。填名称如「实勘问卷」。
2. 建好后进应用详情，记下三个值：**AppKey、AppSecret、AgentId**。
   - AppSecret **只给 serverless 用**，绝不进小程序前端代码、绝不进 git。
3. 「权限管理」里申请/开通：
   - **钉钉登录免登**（`getAuthCode` 换 userid，用来记「谁填的」）；
   - 多维表读写权限（Notable.Base.Read.All / Write.All）——注意实际写多维表**由 serverless 拿这套凭据做**，不是小程序直连。
4. 「开发配置 / 安全设置」→ **服务器出口 IP 白名单**：这里要填 serverless（FC）的出口 IP/域名（等第 2 步 FC 建好后回填）。
5. 「版本管理与发布」→ 提交版本 → **组织内发布授权**，这样估价师能在钉钉工作台里打开它。

**给我**：AppKey、AppSecret、AgentId（AppSecret 走安全渠道，别贴进 git/聊天明文）。

## 2. 阿里云函数计算 FC（serverless broker，唯一持密钥处）

**去哪**：阿里云函数计算控制台 https://fcnext.console.aliyun.com/ ，需**企业实名认证**的阿里云账号。

**做什么**：
1. 创建**函数**：选「Web 函数」或带 **HTTP 触发器**的函数；运行时 Python 或 Node 均可（我按你选的写）。
2. 在函数的**环境变量**里配以下值（**这是密钥的家，不进 git**）：
   - `DINGTALK_APP_KEY` / `DINGTALK_APP_SECRET`（第 1 步的小程序凭据）
   - `NOTABLE_BASE_ID`（多维表 baseId，你 .env 里已有的那个 `6LeBq…`）
   - `NOTABLE_SURVEY_SHEET`（「实勘问卷」表的 sheetId，见第 5 步/一期 seed 脚本会打印）
   - `AMAP_KEY`（第 3 步的高德 Key）
   - `NOTABLE_OPERATOR_ID`（操作人 unionId，你 .env 里已有）
3. broker 要对小程序暴露 **4 个接口**（我来实现，逻辑复用现有 `src/dingtalk/notable.py` 的 `NotableClient` + `src/questionnaire/backend.py`）：
   - `saveDraft`：写/更新一行草稿（状态＝草稿）
   - `loadDraft`：按问卷ID 取一份续填
   - `submit`：把状态改「已提交」
   - `prefillGeo`：收 GPS → 调高德 → 回地理因素**事实**
   - **写多维表的行形状必须照** `src/questionnaire/backend.py::response_to_fields`（问卷ID/状态/填报人/更新时间/类别 平铺 + 「问卷内容」JSON）——一期已把这个契约固定下来，办公端就按它读。
4. 记下函数的**公网访问域名/出口 IP**，回填到第 1 步钉钉的出口白名单。

**给我**：你选的运行时（Python/Node）、函数触发方式，以及部署好后的调用域名。密钥你自己配进 FC 环境变量即可，不必给我。

## 3. 高德开放平台（地图预填「事实」）

**去哪**：高德开放平台控制台 https://console.amap.com/ 。

**做什么**：
1. 注册开发者 →「应用管理」→ 创建应用 → 「添加 Key」。
2. **服务平台选「Web 服务」**（REST API，给 serverless 后端调用；不是「Web 端 JS」也不是「小程序」那种前端 Key）。
3. 会用到两个接口：**逆地理编码**（经纬度→地址）、**周边搜索/POI**（附近公交站、最近地铁、周边配套）。
4. 把 Key 配进**第 2 步 FC 的环境变量** `AMAP_KEY`，**不进小程序前端**。
5. 红线：接口**只填事实**（几个站、多远），**好/中/差档次估价师自己定**，系统不做「距离→档次」映射（铁律 #7）。

**给我**：高德 Web 服务 Key（配进 FC 即可，或走安全渠道给我调试用）。

## 5. 密钥怎么管（安全红线，务必照做）

| 值 | 放哪 | 绝不放哪 |
|---|---|---|
| 钉钉 AppSecret、高德 Key | **FC 环境变量**（或阿里云凭据管家 KMS） | 小程序前端、git |
| 钉钉 AppKey（相对公开） | 小程序前端可有 | —— |
| 多维表 baseId / operatorId / surveySheetId | 办公端 `.env`（已 gitignore）+ FC 环境变量 | git |

- 小程序前端**只**持 AppKey + 调 serverless；一切换 token、写库都在 serverless。
- 办公端 `.env` 那套多维表凭据**一期已用、不变**，只需**加一行** `NOTABLE_SURVEY_SHEET=<实勘问卷表sheetId>`。

## 6. 联调顺序（先易后难，每步能单独验）

1. **现在就能做（不需二期任何账号）**：仓库根 `.env` 配好承载层那套 + 跑
   `uv run python tools/survey_seed.py`
   （往真多维表插一行假「已提交」问卷、打印 sheetId）→ 按提示把 `NOTABLE_SURVEY_SHEET=<sheetId>` 加进 `.env`
   → 起办公端，出报告页点「**从实勘问卷拉取**」→ 应看到这行并预填出表单。**这验通了「办公端读真多维表」这一环。**
2. **高德 Key 到手** → 让我给 serverless 的 `prefillGeo` 单测：curl 一个经纬度，看回不回 POI 事实。
3. **FC broker 部署** → 用 Postman/curl 打 `saveDraft`/`submit` → 去多维表网页看「实勘问卷」表有没有写进、行形状对不对。
4. **钉钉小程序前端接 broker** → 真机在钉钉里打开：免登 → 地图预填 → 填 → 暂存 → 换设备续填 → 提交。
5. **回办公端**「从实勘问卷拉取」→ 应看到真机提交那份 → 预填 → 估价师选实例 → 比较法 → 出报告 + 台账。
