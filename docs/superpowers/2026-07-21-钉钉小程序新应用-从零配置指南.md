# 钉钉小程序「新应用」从零配置指南（替换类型选错、无法正式发布的旧应用）

> 2026-07-21。旧应用创建时**工作台应用类型选错**、钉钉又**不支持事后更改**（报错「暂不支持更改工作台应用类型」），导致只能发体验版、不能正式发布。
> 解法＝**新建一个类型正确的企业内部应用**，把 `miniprogram/` 代码搬过去发布。本指南＝你从 0 要点的每一步 + 要开的权限。
> 代码侧无需改动（除非走 §7 的 B 方案）；你在钉钉后台配好后，broker 只换 key/secret 的**值**再重部署即可。

---

## 0. 目标架构（一句话）

**新应用「一肩挑」**：同一个企业内部应用同时具备 ①小程序能力（可发布到工作台）②多维表读写权限 ③通讯录/免登权限。
这样和旧应用职责一样、只是类型正确；**broker 代码不动**，只把环境变量里的 `DINGTALK_APP_KEY/SECRET` 换成新应用的值，`baseId / sheetId / operatorId` 保持不变。

> ⚠ 唯一不确定点：新应用能否读写**旧应用建的那张多维表 base**。多维表是组织级文档、按「应用权限 + 操作人 unionId」授权，新应用授权后用同一 operatorId 大概率能访问；万一不行，见 §8 兜底。

## 1. 建应用（关键：类型必须选「小程序」）

1. 电脑浏览器打开钉钉开放平台 `open.dingtalk.com` → 用**管理员**账号登录。
2. 「应用开发 → 钉钉应用 → 企业内部应用 → 创建应用」。
3. **应用类型：选「小程序」**（❌ 不要选「H5 微应用」——旧应用就是这里选错、且改不了）。
4. 填：应用名称（如「实勘问卷」）、描述、图标（JPG/PNG，≥240×240px，1:1，≤2MB，无圆角）；开发方式＝**企业自主开发**。
5. 确定创建。

## 2. 记录凭据（填进 broker，绝不进 git）

「基础信息 → 应用信息」里抄下并妥存：

| 项 | 用途 |
|---|---|
| **AppKey（Client ID）** | broker 环境变量 `DINGTALK_APP_KEY` |
| **AppSecret（Client Secret）** | broker 环境变量 `DINGTALK_APP_SECRET`（只显示一次，务必存好） |
| **AgentId** | 备用 |
| **小程序 MiniAppId** | 钉钉开发者工具关联/上传用 |

> 旧应用的 Client ID 是 `dingidtohgvdjwxmtvw7` / MiniAppId `5000000006808190`——**新应用会是另一套，全部以新的为准。**

## 3. 权限管理（要开的权限点清单）

「权限管理」里逐个搜索并**申请/开通**下列权限（企业内部应用一般即时生效）：

| 能力 | 权限点（在权限管理里搜关键字） | 我们哪里用 |
|---|---|---|
| 免登换身份 | **免登**相关 + **通讯录个人信息读**（`Contact.User.Read` / 个人信息读） | 小程序 `dd.getAuthCode` → broker `whoami` 换 userid＝填报人 |
| 查通讯录（取 unionId） | **通讯录成员信息读**（旧应用用的 `qyapi_get_member`） | 取操作人 unionId＝`NOTABLE_OPERATOR_ID` |
| 多维表读 | **多维表读权限**（`Notable.Base.Read.All`） | broker 读「已提交」问卷、草稿 |
| 多维表写 | **多维表写权限**（`Notable.Base.Write.All`） | broker 存草稿 / 改状态 / 删草稿 |

> 权限点的**显示名称以钉钉后台当前界面为准**（钉钉会调整措辞）；按上面「能力」对着搜即可。多维表两项是重点，少一个 broker 读/写就会 403。

## 4. 开发配置（安全设置）

「开发配置 → 安全设置」：

| 栏位 | 填什么 |
|---|---|
| **HTTP 可信域名** | broker 域名 `zhenghee-report-bmpupipvct.cn-hangzhou.fcapp.run`（小程序 `dd.httpRequest` 才能调 broker；要协议就带 `https://`） |
| IP 白名单 | **清空/不启用**（FC 出口 IP 不固定，启用反而挡死 broker 调钉钉） |
| 重定向 URL（回调域名） | 同 broker 域名占位即可（免登走 `dd.getAuthCode`，不实际用它） |

客户端能力：小程序里用到 **定位 `dd.getLocation`**（地图预填）和 **拍照/相册 `dd.chooseImage`**（现场照片）——这些是小程序端能力，真机首次调用会弹系统授权；如后台有「客户端权限」开关，一并打开。

## 5. 用钉钉开发者工具关联新应用 + 上传代码

> CLI（`ding upload`）路线因 app scope 走死，**只走 GUI**。

1. 装/打开「钉钉开发者工具」IDE → 扫码登录（管理员/开发者身份）。
2. **新建项目**，绑定 §1 建的新应用（选其 MiniAppId），目录选 `/Volumes/Elements/workspace/test/估价报告系统/miniprogram`。
3. 编译预览，确认入口页正常、无红错。
4. 右上「上传」→ 版本号 `1.0.0`。
5. （代码里 `ding.config.json` / `mini.project.json` 若残留旧 MiniAppId，开发者工具重新绑定新应用后以工具为准；`miniprogram/` 业务代码不含硬编码 appid，无需改。）

## 6. 发布 + 设可见范围（这一步才是"正式发布"，绕开旧应用的坑）

1. 网页后台「版本管理与发布」→ 找到 `1.0.0` → **发布**。
2. **设置可见范围**：初次发布只有创建者能在工作台看到；把要用的**估价师/部门**加进可见范围，他们的钉钉工作台才会出现该小程序。
3. （需要的话仍可先设**体验版** + 加体验成员做灰度，验收 OK 再正式发布。）

## 7. 改 broker 环境变量 + 重部署

**A 方案（推荐，新应用一肩挑，broker 代码不动）：**
1. 阿里云 FC 控制台 → 函数环境变量：把 `DINGTALK_APP_KEY` / `DINGTALK_APP_SECRET` 换成**新应用**的值；`NOTABLE_BASE_ID` / `NOTABLE_OPERATOR_ID` / `NOTABLE_SURVEY_SHEET` / `AMAP_KEY` **保持不变**。
2. broker 代码/包无需重打（除非同时有其他改动）；改完环境变量**重新部署函数**使其生效。
3. 冒烟：
   ```bash
   BASE=https://zhenghee-report-bmpupipvct.cn-hangzhou.fcapp.run
   curl -sS "$BASE/"                                                   # {"ok":true}
   curl -sS -X POST "$BASE/" -H 'Content-Type: application/json' \
     -d '{"action":"whoami","payload":{"authCode":"bogus"}}'          # 期望「免登失败：不存在的临时授权码」＝新应用免登通
   ```

**B 方案（兜底：若新应用读不了旧多维表 base）：** 旧应用继续管多维表、新应用只管小程序免登。此时 broker 需要**两套凭据**（`DINGTALK_APP_KEY/SECRET` 走多维表＝旧应用；新增 `DINGTALK_MINIAPP_KEY/SECRET` 走免登＝新应用），`identity.py` 改成用新应用的独立 token。**这套代码改动交给我做**——你只要告诉我走了 B 方案 + 新应用的 key/secret 配到哪个变量名。

## 8. 多维表访问确认（A 方案的关键验证）

重部署后，真机走一遍**提交问卷**（写多维表）+ 办公端**拉取**（读多维表）：
- 通了 → A 方案成立，收工。
- 报 403 / 无权限 → 新应用还没能访问旧 base。处理：① 把该多维表 base **分享给操作人（operatorId 那个人）/新应用**；② 或确认 §3 的多维表读写权限已对新应用开通；③ 仍不行则转 **B 方案**（找我改 broker）。

## 9. 验收清单

- [ ] 新应用类型＝**小程序**，可在「版本管理与发布」正常**发布**（不再报「不支持更改类型」）
- [ ] 可见范围加了估价师 → 他们工作台能打开
- [ ] 免登显示「填报人:姓名」（新应用 whoami 通）
- [ ] 地图预填 / 拍照 / 提交 / 删草稿 全链路通（顺带过 `2026-07-21-开发部署与真机校准手册.md` §6 的三处待校准）
- [ ] 办公端「从实勘问卷拉取」读到新提交的问卷

## 10. 与旧应用的关系

- 旧应用可**保留**（A 方案下多维表凭据换到新应用后，旧的闲置无害；也可停用）。
- 旧应用上已发布的体验版小程序：新应用发布后引导用户用新入口即可；旧的可下架。
