# 设计：4 个新类别 + 委托评估协议书 + 下载点选

- 日期：2026-07-17
- 分支：`feat/new-categories-dual-report`
- 状态：设计已确认（用户口头认可三项默认取值），进入实施计划
- 关联铁律：主要触及 §2 铁律 #1（金样精确复现）、#2（知识在 Excel 算术在 Python）、#7（不替他填）；不动 #4/#5（台账只增不改 / 快照自洽）

## 0. 一句话

把系统支持的类别从 3 类（农用/办公/商业）扩到 7 类（+住宅/工业/停车场用地/建设用地），
并在出报告时**同时产出两份文书**——房地产估价报告 + 委托评估协议书——前端点选下载哪份。

## 1. 目标与非目标

**目标**
1. 新增 4 个类别：住宅、工业、停车场用地、建设用地。
2. 新增第二种文书「委托评估协议书」，四类通用。
3. 出报告页支持下载点选：估价报告 / 委托评估协议书 / 打包两份。
4. 每个新类别锁**算术金样**（比较法比准价格重算 = Excel 缓存值）。

**非目标（本轮不做）**
- 不做新类别的**报告正文金样**（无真实签发报告可比，见 §3）。
- 不做委托评估协议书的收费差额计费率**自动测算**（浙价服〔2005〕6 号，属执业收费标准，§8）。
- 不重构现有 3 份模板（office/farmland/commercial.docx）——保其金样不动。
- 不做钉钉/报告编号/实例推荐（既有 backlog，无关本轮）。

## 2. 关键事实（决定设计形态）

- **报告模板本质是一份文档的两个 shape**：现有 3 份模板互相 70–78% 相同，差异几乎全是
  「房产 vs 土地」用词（房屋/㎡/365 天 vs 土地/亩/年租）。
- **4 个新类别按口径干净落到这两个 shape**（已核 Excel 单位）：

  | 新类别 | shape | 单位 | 年租赁公式 |
  |---|---|---|---|
  | 住宅 | 房产 | 元/㎡·天，面积㎡ | area × price × 365 |
  | 工业 | 房产 | 元/㎡·天，面积㎡ | area × price × 365 |
  | 停车场用地 | 土地 | 元/亩·年，面积亩 | area × price |
  | 建设用地 | 土地 | 元/亩·年，面积亩 | area × price |

- **4 份新 Excel 用通用 sheet 名**（`房地产实地查勘记录表` / `房地产比较法`，同农用/商业；
  仅办公用特殊 sheet 名），字段抽取大概率直接复用，实施时逐类别验证。
- **委托评估协议书**是 28 段固定法律文本，变量只有：甲方名称、标的基本情况、收费合计+大写、
  日期几处；四类**类别无关**，做一份通用模板即可。
- 文件夹里的「房地产估价报告（租金通用模板）.docx」= office.docx 的**未模板化原件**
  （结构一致，0 个 jinja token，值是某真实案例）；可作房产 shape 模板的改造基底。
- 提供的 4 份 Excel 面积均为 1342.59，是**构造样例**而非真实签发案例。可用于锁算术金样
  （缓存自洽），真实案例待用户后续从对方取得后再重锁 + 微调用词。

## 3. 正确性标准（Approach A，用户已选）

铁律 #1 有两层，新类别按下述落地：

- **算术金样（真红线）**：比较法三行在 Python 重算，必须等于 Excel 比较法 sheet 的缓存值。
  4 个新类别**每类锁一条**，进 `tests/test_engine_golden.py`。这是可做、且必须做的。
- **报告正文金样**：现有三类比对真实签发报告（`案例素材/正恒评报字…docx`）。新类别**没有**
  这种参照，故**只做结构性渲染测试**（能渲染、关键 jinja 已填、无 §5 坑 10/11 的垃圾行），
  **不做逐段正文金样**。
- 新类别报告页脚/交付清单**显式标注**：「本类别报告为结构渲染，未经逐段金样校验，交付前
  须执业估价师终审用词与格式」。此标注是 Approach A 的诚实交底，不可省。

## 4. 架构与组件

### 4.1 模板（templates/）

新建两份**完全 jinja 化**的 shape 模板（现有 3 份不动）：

- `lease_building.docx`：从「租金通用模板」改造，房屋/㎡/365 用词，全变量 jinja 化 ← 住宅、工业
- `lease_land.docx`：从 `farmland.docx` 改造为完全 jinja 化（去掉硬编码样例日期/人名）← 停车场用地、建设用地
- `entrustment_agreement.docx`：委托评估协议书通用模板，jinja 化甲方/标的/收费/日期 ← 四类共用

文件名一律 ASCII（守 §5 坑 7）。多个 Category 映射到同一 shape 文件（多对一）。

### 4.2 代码改动（都是接线，单一职责）

- `src/model.py`
  - `Category` 加 4 值：`RESIDENTIAL="住宅"`、`INDUSTRIAL="工业"`、`PARKING_LAND="停车场用地"`、
    `CONSTRUCTION_LAND="建设用地"`（值仍是中文，遍布 JSON/台账，符合 §5 坑 7 的「类别值不动」）。
  - `is_land` 从「== AGRICULTURAL」泛化为「∈ {农用, 停车场用地, 建设用地}」，作为 land 口径唯一来源。
- `src/engine/annual.py`
  - `×365` 判定由「非农用」改成「非 land」，复用 `Project.is_land`/同一 land 集合，杜绝双实现漂移。
- `src/renderer/render.py`
  - `TEMPLATE_FILENAMES` 加 4 项：住宅/工业 → `lease_building.docx`；停车场/建设用地 → `lease_land.docx`。
  - `build_context` 补齐新 shape 模板需要的变量（若现有 context 缺，如完全 jinja 化后暴露的
    价值时点/机构地址/查勘人等），使其真正通用。
- `src/renderer/agreement.py`（新增）
  - 独立的协议书 context builder + render 路径，与估价报告解耦。收费合计取自入参（手填），
    大写复用 `src/prose/capital.py`。
- 抽取层（`src/extractor/*`）：逐新类别验证字段映射，通用 sheet 名应可复用；有偏差再补。
- `src/web/app.py`：生成接口一次产出两份 docx，返回两个可下载句柄（或按需渲染协议书）。
- `src/web/static/index.html`：生成后出现「下载估价报告 / 下载委托评估协议书 / 打包下载两份」。

### 4.3 三项默认取值（用户已认可）

1. **收费手填**：估价师填「收费合计」，大写自动生成；差额计费率表暂作模板固定文本。
   理由：浙价服差额计费属执业收费标准 + 域算术，按 §8 不编码进系统。
2. **协议书不进台账**：协议书无估价算术可复现，按「同项目数据当场渲染」；台账仍只管估价，
   不碰铁律 #4/#5。
3. **执行先竖切一刀**：先做住宅(房产)+停车场用地(土地)+协议书+下载点选，两个 shape 各验一次；
   再补工业+建设用地（两 shape 的近乎复制）。

## 5. 数据流

出报告（新类别）：
```
Excel/表单 → 抽取 Project(category=新类别) → 比较法引擎重算比准价格（算术金样锁死）
  → build_context → docxtpl 渲染 lease_building/land.docx  → 估价报告.docx
                  → agreement.build + 手填收费 → entrustment_agreement.docx → 协议书.docx
  → 前端点选下载哪份 / 打包
```

## 7. 风险与缓解

- **报告用词执业合规性**：新类别（尤其土地类）范围/单位/法定用语，用户（建设方）无法核验，
  须执业估价师终审。缓解：报告标注 + 交付清单硬性要求（§3）。
- **金样来自构造样例**：现锁的算术金样基于文件夹提供的 Excel（面积均 1342.59）。缓解：真实
  案例到位后重锁金样并微调；测试结构使重锁只需替换 Excel + 期望值，不动管线。
- **完全 jinja 化暴露缺失变量**：新 shape 模板去硬编码后，`build_context` 可能缺变量导致渲染
  空槽。缓解：结构渲染测试断言关键槽非空。
- **抽取层字段偏差**：个别新类别实勘表列序可能与现有不同。缓解：逐类别验证 + 字段映射测试。

## 8. 谁能拍板什么（承接 docs/README §8）

- 产品/工作流（下载点选形态、执行顺序、收费手填 vs 自动）：用户拍板 —— 已认可。
- 执业准则（新类别报告用词、收费标准、法定文书格式）：须执业估价师 —— 报告标注 + 终审兜底。
