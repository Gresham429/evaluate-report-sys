## 0. 目标与非目标

**目标**：办公端用钉钉扫码登录拿到真 **userid** → 存会话 → 权限「只看自己 / 管理员看全部」自动生效，免手填 `OFFICE_OPERATOR_ID`。

**非目标**：
- 强安全边界——一人一机、本机应用、弱威胁模型（`.env`/数据本地可改，登录拦不住）。登录主要为**身份自动对上**，非强鉴权。
- 手机端 / broker 改动——**纯办公端**，不碰 broker、不重部署、不动小程序。
- 每次登录——登录一次记会话；关掉重开再登。

## 1. 关键：登录得到的是 unionId，须换成 userid

OAuth2 网页登录链路拿到的是 **unionId/openId**（`contact/users/me`），而问卷「填报人」是 **userid**（小程序免登 `getuserinfo` 来的，如 `10076`）——两者不同命名空间。若直接拿 unionId 当操作人，和 `NOTABLE_OPERATOR_ID`（也是 unionId）一样**匹配不到任何问卷**（真机已踩过）。

故登录须多一步 **unionId → userid**：拿应用 access_token 调 `topapi/user/getbyunionid`（办公端已有应用 token + 通讯录读权限，`config.build_client()`/`NotableClient.access_token()`）。`set_operator` 存的必须是 **userid**。

## 2. 机制（纯本机 OAuth2 授权码流）

1. 办公页点「钉钉登录」→ `GET /auth/login` → 后端生成随机 `state`（存会话防 CSRF）→ 302 到：
   ```
   https://login.dingtalk.com/oauth2/auth?client_id=<YIDA_APP_KEY>
     &redirect_uri=<enc http://127.0.0.1:8765/auth/callback>
     &response_type=code&scope=openid&prompt=consent&state=<state>
   ```
2. 用户手机钉钉扫码 → 钉钉 302 回 `http://127.0.0.1:8765/auth/callback?authCode=...&state=...`
3. `GET /auth/callback`：
   - 校 `state` 与会话一致，否则 400（防 CSRF/重放）。
   - `POST https://api.dingtalk.com/v1.0/oauth2/userAccessToken`，body `{clientId:<AppKey>, clientSecret:<AppSecret>, code:<authCode>, grantType:"authorization_code"}` → `userAccessToken`。
   - `GET https://api.dingtalk.com/v1.0/contact/users/me`，header `x-acs-dingtalk-access-token: <userAccessToken>` → `{unionId, nick, ...}`。
   - `unionId → userid`：`POST https://oapi.dingtalk.com/topapi/user/getbyunionid?access_token=<应用token>`，body `{unionid}` → `{result:{userid}}`。
   - `session.set_operator(userid)`（并存显示名 `nick`）→ 302 回 `/`。
4. `GET /auth/logout` → `session.clear_operator()` → 302 回 `/`。

> **待真机校准**（同当年免登，一次即通）：`oauth2/userAccessToken` / `contact/users/me` / `getbyunionid` 的端点、请求头、返回字段路径按现行钉钉文档写，真机扫一次校准；若 `me` 直接回了 userid 就省掉 getbyunionid 那步。

## 4. 会话与优先级（接 #3 与管理员名单）

- `current_operator()`：**会话（登录）> `OFFICE_OPERATOR_ID`（.env 过渡）> ""**。登录后即用真 userid；未登录回退 .env 过渡值（现状不变，交付/未配也能用）。
- 管理员：仍按 `OFFICE_ADMINS`（userid 名单）——登录的 userid 命中名单即管理员。
- `visibility_filter()` 不变（普通只看自己、管理员看全部、"" fail-closed）。

## 5. 测试

- `oauth.py` 单测：`build_auth_url` 参数与编码；`exchange`/`me`/`userid_by_union` 用假 transport（200 正常 + 4xx→ValueError 映射）。
- `/auth/*` 端点单测（monkeypatch 掉钉钉调用）：`login` 302 到钉钉且 state 入会话；`callback` 假 OAuth 全链路 → `set_operator(userid)` → 302；`state` 不符 → 400；`logout` 清会话。
- **真机门（你做）**：真扫一次，校准三处端点形状；若 `contact/users/me` 403 → 权限管理补 `openid`/个人信息读。

## 6. 安全取舍

- `state` 防 CSRF；回调绑 `127.0.0.1`（钉钉只回本机）；`client_secret` 只在后端、不进前端。
- 坦白：一人一机弱边界，登录为「身份自动对上、免手填」，非强鉴权。
