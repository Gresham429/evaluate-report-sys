# 基础表版本管理（多维表为源、本地拉取、按类别选生效版）· 设计

> 2026-07-20。用户确认设计后成文。目标：把 7 类基础表做成**中心（多维表）统一维护、本地拉取缓存、每类别可选生效版本**的版本管理，并让打包的 exe 离线开箱即用。

## 1. 目标
- **多维表**保存每类别的多个基础表版本（不可变、指纹去重、时序）。
- 本地**「从钉钉拉取」**把版本同步到本机；**平时离线出报告**用本地缓存（Q1=A）。
- 每类别可在列表里**选一个「当前生效版本」**（全局默认、每台机器各选，Q2=A），新报告默认用它。
- 基础表页做成**手风琴**：类别合并一行 → 展开列该类别所有版本（时间倒序）、最新标 `latest`、当前生效高亮、可「设为当前」。
- **打包**：exe 内置 7 张默认，首次运行本地为空时铺一份（离线可用）；之后可拉取更新。

## 2. 现状（落到代码）
- 版本库 `src/knowledge_base/store.py`：`BaseTableStore`，按 `(类别, 指纹)` 存版本，`{类别}-{指纹}.json` + `台账.json` 索引（含 `导入时间`）。`current(category)` = 按导入时间取**最新**；`load(category, fingerprint=None)` 按指纹取指定版，载入时重算指纹自校验防篡改。
- 可插拔后端 `src/knowledge_base/backend.py`：`LocalFileBaseTableBackend`（本地文件）/`InMemoryBaseTableBackend`（契约）；`src/knowledge_base/notable_backend.py`：`NotableBaseTableBackend`（多维表一张表，行 `种类=版本/索引`，内容 JSON 在 `内容` 字段）。三者同接口：`write_version / read_version / version_exists / read_index / append_index`。
- 后端选择 `src/dingtalk/factory.py::base_table_backend_for(path)`：`承载后端=多维表` 且配了 `base_table_sheet()` → Notable 后端；否则本地。
- 唯一写路径 `BaseTableStore.import_from_excel(xlsx)`（读 `比较因素条件说明表（基础表）` sheet → Knowledge → 指纹 → 写版本 + 台账）。
- Web：`GET /api/factors(category, fingerprint?)`、`GET /api/base-tables`（列版本）、`POST /api/base-tables`（导入 Excel）；前端有「基础表」页。
- 打包 `build_exe.py`：**刻意不带 `data/`**（升级不覆盖用户数据）；无首次运行播种。
- 7 类：农用/办公/商业/住宅/工业/停车场用地/建设用地（`src/model.py`）。本地 `data/基础表` 现已备齐 7 张（本次会话导入）。

## 3. 关键决策
- **D1（Q1=A）联网拉取、离线用**：基础表**存储恒本地**；多维表是**同步目标**，经显式「拉取」拿版本。
- **D2（Q2=A）全局生效版本、每机各选**：本地存一份 `类别→生效指纹` 配置；缺省回落到 `current()`（最新）。
- **D3 基础表与 `承载后端` 开关解耦**：`承载后端=多维表` **不再**把基础表**存储**切到多维表（台账/实例库/实勘问卷仍随开关走）。基础表一律本地存储 + 显式多维表同步（拉取/导入推送）。理由：D1 要离线可用，live-read 多维表做不到；且解开了「开关一刀切」——办公端可同时「问卷走多维表」与「基础表本地」。
  - **迁移影响**：`factory.base_table_backend_for` 改为**恒返回本地后端**（不再看 `承载后端`）；出报告/`factors`/导入的 store 都是本地。原先假设"基础表随开关走多维表"的测试（`test_web_base_tables` 及 notable 基础表往返测试）需相应更新为"本地存储 + 独立 sync"。台账/实例库/问卷的开关行为**不动**。
  - **同步用的多维表客户端与开关无关**：拉取/推送只需**凭据 + `base_table_sheet`**（不看 `承载后端`）。用一个"按凭据直建 NotableBaseTableBackend"的辅助（如 `config.notable_base_table_backend()`），凭据/表未配则视为"多维表不可用"。
- **D4 导入即推送**：`import_from_excel` 写本地后，若多维表已配（凭据 + `base_table_sheet`），把该版本也 `write_version` 进多维表（幂等，`version_exists` 去重）。这是新版本进多维表的来源。

## 4. 数据模型
- **本地版本库**：`data/基础表/{类别}-{指纹}.json` + `台账.json`（不变）。
- **生效版本配置**：新增 `data/基础表/生效版本.json` = `{ "农用": "<指纹>", ... }`。缺该文件/缺某类 → 该类回落 `current()`（最新）。写入即持久化。
- **多维表版本库**：`NotableBaseTableBackend`（现有）——拉取源、导入推送目标。

## 5. 三个动作
- **导入 Excel**（联网/本地皆可）：`import_from_excel` 写本地新版本；若多维表已配则同版 `write_version` 推送多维表（D4）。返回 `{类别, 指纹, 是否新版}`。
- **拉取**（基础表页按钮）：读多维表 `read_index` + 各版 `read_version`，对本地缺失的指纹 `write_version` 写入本地（并集，已有不动）。离线/多维表未配 → 明确提示、不崩。返回每类新增/合计版本数。
- **选生效版**：在列表点某版 → 写 `生效版本.json[类别]=指纹`。返回新的生效指纹。

## 6. 初始化与打包
- **现在**：把本地已备齐的 7 张**推送**进多维表当各类别 v1 基线（新脚本 `tools/base_table_provision.py`：遍历 7 类本地 `台账.json` 各版本，`version_exists` 去重后 `write_version` + `append_index` 进多维表）。你正跑多维表模式，脚本跑完基础表页「从钉钉拉取」即验证。
- **打包**（改 `build_exe.py` + 首次运行播种，遵守「升级不覆盖」）：
  - 新增受版本管理的 `resources/默认基础表/`：7 张 `{类别}-{指纹}.json` + `台账.json`（从当前 `data/基础表` 生成、提交入库；`data/` 仍 gitignore）。
  - `build_exe` 用 PyInstaller `--add-data` 打进包（冻结后在 `sys._MEIPASS`）。
  - 首次运行播种：`src/__main__.py:main()` 里，`data/基础表` **无 `台账.json`（空）** 时，把 `resources/默认基础表/*` 拷进 `data/基础表`；非空则跳过。→ 老用户升级零影响。
  - 播种逻辑放 `src/knowledge_base/seed.py::seed_default_base_tables_if_empty(dest_dir, resources_dir)`，可单测（用临时目录）。

## 7. API 变更
- `POST /api/base-tables/pull` → 拉取（多维表→本地并集）；离线/未配回 409 + 文案，正常回 `{类别: {新增, 合计}}`。
- `POST /api/base-tables/active` body `{category, fingerprint}` → 设生效版；校验该指纹本地存在，写 `生效版本.json`，回 `{category, active}`。
- `GET /api/base-tables`（改）：每类别返回 `{类别, 版本[]（时间倒序，各含 指纹/导入时间/来源文件名/是否latest）, 生效指纹}`，供手风琴渲染。
- `GET /api/factors` / 出报告链路（改）：默认版本从 `current()` 改为**生效版本**（`生效版本.json` 有则用之，否则 `current()`）。集中到一个 `active_fingerprint(store, category)` 辅助函数，所有取"默认版本"处走它。
- `POST /api/base-tables`（导入）：加 D4 推送多维表。

## 8. 前端（基础表页，手风琴）
- 顶部「从钉钉拉取」按钮 → `POST /api/base-tables/pull`，转圈 + 结果提示（新增 N 版 / 已最新 / 离线提示）。
- 列表：每类别一行（类名 · 版本数 · 当前生效时间 · 若生效=最新则标 `latest`），点击展开。
- 展开：该类别版本时间倒序；每行「导入时间 · 指纹短 · 来源文件名」；最新标 `latest`；当前生效行高亮 ● +「当前生效」；非生效行有「设为当前」→ `POST /api/base-tables/active`，成功后刷新该组。
- 纯原生 JS（沿用单文件 `index.html` 风格），改了**必须起服务浏览器实测**（本项目铁律：UI 状态切换单测拦不住）。

## 9. 报告集成
- 出报告 / `factors` / 预填下拉：取某类别"默认基础表"处全部改走 `active_fingerprint`。台账仍快照**当时那版**（不变），故切生效版只影响**新**报告，旧报告可复现。

## 10. 错误处理 / 边界
- 拉取：离线 / 多维表未配凭据或 `base_table_sheet` → 409 + 明确文案（沿用 `/api/online` 三态语义），不崩。
- 生效版指向本地不存在的指纹 → 400；`生效版本.json` 损坏 → 记 warning、回落 `current()`。
- 版本不可变、旧版永不覆盖（沿用 store 承诺）；指纹自校验防篡改。
- 首次播种仅在本地空时执行，绝不覆盖既有版本。

## 11. 测试
- `seed_default_base_tables_if_empty`：空目录播种 7 张、非空跳过（临时目录单测）。
- 生效版本：设/读/回落 `current()`、指向不存在指纹报错。
- 拉取：假 Notable 后端 → 本地并集（新增 + 已有不动）；离线/未配回 409。
- 导入推送：多维表已配时 `import_from_excel` 双写；未配时仅本地（行为不变）。
- `active_fingerprint`：有配用配、无配回落最新。
- 端到端（真机/手动）：基础表页拉取 → 展开 → 设为当前 → 出报告用该版（浏览器实测）。

## 12. 非目标（YAGNI）
- 生效版本**不**做公司级同步（每机本地选，D2）。
- **不**做版本删除/回滚 UI（旧版永不覆盖，够用）。
- **不**做多维表并发写锁（导入低频、指纹幂等）。
- 逐因素描述、28 档次、照片仍属小程序 v2，与本设计无关。
