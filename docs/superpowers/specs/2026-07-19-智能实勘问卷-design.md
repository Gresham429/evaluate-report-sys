## 0. 一句话

把实勘表搬进钉钉小程序：估价师**现场手机填**（地图预填地理因素**事实**、逐因素校验、拍照）→ 提交进钉钉多维表 → 回办公室桌面程序拉「已提交」那份、预填出报告表单 → **估价师亲自选可比实例** → 比较法重算(Python) → 出报告 + 台账。**问卷只管采集，算术与渲染仍在 Python（金样红线不动）。**

## 1. 范围

**做（本设计）：** 钉钉小程序问卷前端；serverless broker（替小程序读写多维表）；多维表「实勘问卷」表；办公端拉取适配器；暂存 + 跨设备续填。

**不做（明确延后/排除）：**
- **离线兜底**——现场靠 4G，没信号晚点填/提交，不搞桌面那套「待同步」（用户选最小范围）。
- **系统自动选实例 / 可比性推荐**——铁律 #7，估价师自己选。
- **报告编号不在问卷阶段领**——仍在办公端出报告时领（沿用离线待同步那套 `draw_report_number`）。

## 2. 已敲定决策（2026-07-19，与建设方逐条）

1. **采集对象 = 实勘表**（本次估价对象的具体情况：28 因素各自档次、资产状况逐条描述、基本信息、照片）。**不是基础表**——基础表是估价知识（铁律 #1 只读，改它 = 改 Excel 重导），问卷一个字都不动它。（用户一度口误说"更新基础表"，已澄清为实勘表。）
2. **三样「智能」全要**：移动引导表单 + 逐因素校验 + 地图预填地理因素事实。
3. **平台 = 钉钉小程序前端 + serverless broker + 多维表**，**不维护常驻服务器**。理由：小程序前端**不能塞 `app_secret`**（谁都能扒），写多维表要密钥换 token 必须服务端；但服务端可用 **serverless（阿里云函数计算）**——按调用付费、零日常运维，不是常驻 VM。
4. **「一键」= 预填好、估价师选实例**：问卷预填 → 办公端载入免二次录入 → **估价师亲自选可比实例** → 比较法 → 出报告。系统不自动挑实例（#7）。
5. **不做离线兜底**（现场在线提交）。
6. **暂存 + 跨设备续填**：多维表记录带 `状态`（草稿|已提交）；现场手机填一半→暂存→回办公室换设备打开同一份补完→再提交；**办公端只拉「已提交」**。全程在线，非离线兜底。
7. **地图 = 高德**（钉钉地图本身即高德）；接口**只填事实**（附近几个公交站、最近地铁多远、周边配套），**好/中/差档次估价师自己定**，系统不做「距离→档次」映射。
8. **照片跟着报告走**（渲染已支持附件页 `collect()`）。

## 3. 架构与数据流

```
现场（钉钉小程序·手机）
  钉钉免登拿身份(getAuthCode→userid) → 取一次 GPS → serverless 调高德 POI/逆地理 → 预填地理因素「事实」
  → 估价师逐因素核对/定档次 + 基本信息 + 资产状况描述 + 拍照
  → [暂存] 经 serverless 写多维表一行，状态=草稿（可跨设备再打开续填）
  → [提交] 状态=已提交
办公桌面程序（现成，Python）
  拉多维表「已提交」问卷 → 映射成实勘表数据（基本信息/28 因素档次/资产状况/照片）
  → 预填出报告表单 → 估价师选可比实例 → 比较法重算(Python) → 出报告 + 台账（出报告时领号）
```

**关键：现场手机绝不直连多维表**（密钥不能进前端）；一切读写经 serverless。**办公端不碰小程序/serverless**，它照旧用本地 `NotableClient` 直读多维表「已提交」记录（同承载层那套凭据）。

## 4. 三个组件（边界清楚、可独立理解与测试）

### 4.1 多维表「实勘问卷」表 + serverless broker
- **表字段**：问卷ID / 状态(草稿|已提交) / 填报人(userid) / 基本信息(19 项) / 28 因素档次 / 资产状况逐因素描述 / 照片 / GPS / 更新时间。可给脚本自动建（同 `tools/notable_provision.py`）。
- **serverless（阿里云函数计算）**：持 `app_secret` 换 accessToken、替小程序读写此表、钉钉免登换 userid。**复用现有 `NotableClient` 的调用形状**（可把该客户端逻辑打包进函数）。
- **照片**：优先多维表附件字段；若多维表不支持附件列，则存钉盘/图床、表里放 URL（**待验**）。
- **接口（小程序 ↔ serverless）**：`saveDraft`（写/更新草稿）、`loadDraft`（按问卷ID取）、`submit`（状态→已提交）、`prefillGeo`（GPS→高德→地理因素事实）。

### 4.2 钉钉小程序前端
- 逐因素引导表单（档次下拉，选项取自**基础表因素定义**）、地图预填（经 4.1 `prefillGeo`）、逐因素校验（移植 `src/validator/` 的规则、**只提示不阻断**）、拍照、暂存/续填/提交。
- **前端不碰任何密钥**，一切读写经组件 1 的 serverless。

### 4.3 办公端拉取适配器（桌面程序内新增）
- 列「已提交」问卷 → 估价师选一份 → 拉取 → **映射成 `Project`/实勘数据**（对到 `src/extractor/` 现有实勘表字段：基本信息 / 因素档次 / 资产状况描述 / 照片）→ 预填现有出报告表单。之后全走现成管线（选实例→比较法→出报告→台账）。
- **映射表是本组件核心**：问卷字段 ↔ `extractor` 实勘表字段（含照片附件的落地）。

## 5. 铁律处置

- **#1 金样**：比较法、渲染全留 Python，问卷只采集、不碰算术。
- **#3 运行时零 AI**：地图 POI 是确定性检索、发生在**采集**阶段；报告生成阶段无任何模型调用，可复现不变。
- **#5/#6 快照自洽/存当时那份**：预填的事实经估价师确认后**随实勘数据进台账快照**，出报告用存的那份，**不在渲染时重查地图**（否则同份报告今明查出的周边不一样）。
- **#7/#8 不替他填、判断交给人**：接口只给事实，档次估价师定，系统不做「距离→档次」映射、不推荐实例。
- **#9（钉钉改写版）**：问卷数据进公司受控的钉钉多维表；GPS 坐标发高德属外部调用，须合规确认。
