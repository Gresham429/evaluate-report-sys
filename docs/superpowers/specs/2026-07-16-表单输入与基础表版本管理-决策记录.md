## 1. 本轮讨论定下的决策

| | 决定 | 依据 |
|---|---|---|
| 输入方式 | **表单为主**，Excel 导入降级为可选便利 | 用户：「我们输入并不是 excel；而是 excel 里面自带流程需要的输入…当然我们也可以导入填好的 excel 来自动识别」 |
| 基础表来源 | **方案乙**：Excel 是权威，系统存副本，改了重导一次 | 保住 ADR-001 的「改 Excel 基础表即生效」 |
| 版本号 | **内容指纹（哈希）**，非人工填写 | 现有基础表**无任何版本标记**（已实测三份全无），人工填会忘/填错 |
| 旧版本 | **永不覆盖**，可取出重算 | 「能复现」是可复查的前提 |
| 复查范围 | **内部复核** | 用户：「这个是我们自己人来看的」→ 不动报告模板，不需问执业规范 |
| 19 项基本字段 | **全部人工填写，系统不拼凑** | 用户：「不拼凑 实地勘察去填写」 |
| 实例按类别过滤 | **已实现** | 见 §4 |

## 2. 新需求 A：表单输入（未实施）

### 2.1 字段规模（实测，以办公为例）

| | 项数 | 类型 |
|---|---|---|
| 基本信息 | **19** | 自由文本/日期，**全部人工填** |
| 估价对象因素档次 | **28** | 下拉框，5 选 1，选项来自基础表 |
| 估价结果一览表 | 每对象 **5** 项 × N | 序号/权利人/地址/用途/面积（单价与年租赁价值由引擎算） |
| 附件 | — | 已实现 |

**单对象最少 52 项。**

19 项基本字段清单（单元格 → 字段）：
`C2 project_name`、`C3 client`、`C4 client_address`、`C5 legal_rep`、`C6 purpose`、`C7 survey_date`、`C8 value_date`、`C9 materials`、`C10 certificate_status`、`C11 owner`、`C12 address`、`C13 usage`、`C14 scale`、`C15 scope`、`C16 current_status`、`D46 surveyor`、`H2 report_no`、`H3 issue_date`、`H4 work_period`

### 2.2 不拼凑（用户明确要求）

曾建议自动拼 `project_name`（权利人+地址）、`scale`（一览表面积合计）、`work_period`（勘查日期+出具日期）、`scope`/`purpose`（套话默认值），可把人工填写从 19 项降到 8-10 项。

**用户否决：「不拼凑 实地勘察去填写」。**

理由成立——拼凑出的文字进了报告是要签字的，责任不清。让填的人对自己写的字负责。

### 2.3 但要替他核（本文件新增的设计）

用既有校验器机制（**只提示、不阻断**）补一条一致性检查：

```
scale 填「房屋建筑面积723.69平方米…」
一览表 356.29 + 367.4 = 723.69         ✅ 一致

若手滑打成 732.69
→ ⚠ 规模字段写的 732.69 平方米，与一览表面积合计 723.69 不符，请复核
```

**不替他填，但替他核。**

### 2.4 28 个下拉框其实不重

选项**全部来自 Excel 基础表**（如「距区域中心距离＜1KM」/「1-1.5KM」/…），系统已能读出（`src/engine/knowledge.py::extract_knowledge`）。是 5 选 1，不是自由输入。档次一选，指数即可算，估价师能当场看到影响。

### 2.5 鸡生蛋：基础表撤不掉

```
Excel 基础表  ← 必须有。它是知识源，估价师维护它（ADR-001 定的）
Excel 实勘表  ← 可以不要。字段改由表单收
```

用户所说的「输入不是 Excel」指的是**实勘表这一层**。基础表是估价知识本身，不可能撤。

### 2.6 输入抽象层此时该立起来

表单落地后，`/api/extract`（读 Excel）与表单是**两条并行的输入路径**，二者**必须产出同一个 `Project` 对象**。

这正是[比较法引擎与实例库设计 §5](2026-07-16-比较法引擎与实例库-design.md) 提出、而用户当时同意本轮不做（YAGNI，无第二实现）的抽象层。**现在有第二个实现了，该做了。**

## 3. 新需求 B：基础表版本管理（未实施）

### 3.1 场景

```
2026-03  用基础表 v1 出报告，评估结果 2.83
2026-09  估价师调系数，基础表变 v2
2027-01  复查那份 2026-03 的报告
         → 须知道用的是 v1；须能拿 v1 重算出 2.83
```

**光记「用了 v1」不够，得能拿 v1 把结果重算出来。** 故旧版本不可覆盖。

### 3.2 现状：零版本标记（实测）

三份基础表**均无任何版本号、修订日期、生效日期**。今天改了系数，Excel 上看不出任何痕迹——谁改的、何时改的、改前是什么，全无记录。

**版本管理是从零建立，不是给现有机制加界面。**

顺带实测发现基础表 K 列有用户自己的备注，印证它本就设计成可改：
- `K4`：同一小区单套或单层办公用房无需该项修正，整栋或这个园区需考虑临街状况
- `K16`：有隐藏行，有特殊修正项目可展开，可修改

### 3.3 设计

```
data/基础表/
  办公-6584dc9b.json      ← 内容指纹当版本号，不可变
  办公-a1b2c3d4.json      ← 改系数重导 → 新指纹 → 新文件，旧的留着
  农用-56ce11aa.json
  商业-5df34ffb.json
  台账.json               ← 哪版、何时、从哪个文件导入

data/生成台账.json          ← 报告号 → 基础表版本 + 三条实例编号 + 各自市场状况指数
```

**三份基础表的实测内容指纹**：

| | 指纹（2026-07-16 落地实测） | 探索期临时脚本曾记 |
|---|---|---|
| 农用 | `2392ea9d6359` | ~~`56ce11aa5505`~~ |
| 办公 | `95d043e06567` | ~~`6584dc9bf9d2`~~ |
| 商业 | `df20ba03d3fb` | ~~`5df34ffb0b64`~~ |

> 右列是探索期临时脚本算的，**拼接口径未留存**，落地时重定口径后数值不同。
> 指纹的价值在「内容一变即变」，不在具体字符串——无人依赖那三个旧值。
> 左列已写成 golden 测试锁死：口径一改它们全变，那时该红。
> **口径以 `src/knowledge_base/fingerprint.py` 的 docstring 为准**，改它会让
> 全部历史版本号失效。要点：覆盖因素名/档次描述/分值/系数/标尺，**不覆盖
> `Factor.row`**（行号是排版细节，不在 ADR-001 划的知识边界内；但 row 仍要
> **存**，Excel 路径靠它定位比较法表的行——「存」与「进指纹」是两回事）。

> ⚠ **别拿「基础表插一个空行 → 行号后移 → 不该出新版本」当排除 row 的理由**
> ——这个场景根本到不了指纹。`extract_knowledge` 把因素块钉死在 3..30 行、
> 分值标尺钉死在第 31 行，插一行分值行就移到 32，导入直接抛 `ValueError`
> （实测）。规则对，但那个理由是虚构的。

**顺带实测**：基础表 I 列（修正系数）在三份素材里**都是公式**（`=办公房地产比较法!X9`），
系数的真身在比较法表 X 列。故「改系数验指纹会变」这类测试不能直接改 I 列——
openpyxl 存盘丢弃全部公式缓存值（ADR-001 已实证），改完 28 个系数会全塌成 0，
测试因无关原因变绿。须先 `data_only=True` 压平成值再改。

**为何用指纹而非人工版本号**：内容一变指纹即变，改不了也伪造不了。人工填「v1.2」会忘、会填错、会复制粘贴时忘改。

### 3.4 界面明示当前版本

```
当前基础表：办公类 · 6584dc9b · 导入于 2026-07-16 · 来源 办公实勘表、比较法.xlsx
```

**不阻止**使用旧版本（万一 Excel 改了没重导，系统照跑），但用户一眼能看到用的是哪一版。与本项目一贯立场一致：**保留事实，判断交给人**。

## 8. 第三轮：两项缺口的补法（2026-07-16 完成）

### 8.1 缺口①：单位

规则原本就在 `src/prose/composer.py::compose()` 里，提成 `price_unit(category)` / `area_unit(category)` 两个函数复用，**没有新造第二份判断**。单位随数字一起走：

- `/api/compute` 返回 `单价单位` —— 让界面自己去配单位，早晚配错一次
- `/api/extract` 返回 `单价单位`/`面积单位` —— 一览表表头据此标注
- 顺带发现实例列表也犯了同一个病：「成交价 2.52 元」漏了单位，农用的 1410 与办公的 2.52 差 500 倍，一并补上

`compute_from_selection()` 的返回值随之从 `Result` 改为 `(Category, Result)`。

### 8.2 缺口②：重算结果进报告

**关键分歧**：办公 `K49` 是公式直连 `T39`（2.83），但农用 `K49` 是手打的 **1400**，而 `T39` 算出的是 **1399.26**——中间隔着估价师的手工取整。

**用户决定：预填 + 可改，年租赁价值自动跟算。**

```
重算出 1399.26  →  预填进一览表单价  →  估价师可改成 1400  →  年租赁价值自动跟算
      系统的算术              人的判断                     系统的算术
```

与 ADR-001 划的界一致：算术归系统，判断归人。系统**不替他取整**，但**替他算**。

落地：

- 新增 `src/engine/annual.py::annual_value(category, area, unit_price)`，是年租赁价值公式在系统内的**唯一实现**
  - 农用 `面积×单价`；房屋类 `ROUND(面积×单价×365,0)`
  - 用 `Decimal` + `ROUND_HALF_UP` 对齐 Excel 的 ROUND。**内置 `round()` 是银行家舍入**，182.5 会舍成 182 而 Excel 记 183
  - `src/validator/checks.py::_check_table` 原本自带一份实现，改为调用它——两份迟早算出两个数
- 新增 `POST /api/annual-values`：界面改了单价就来问它。**公式不抄一份进 JS**
- 界面新增「用此结果更新一览表」，写回 `unit_price`/`dispersion`/各对象单价，报告印的就是这份数据
- 一览表标注单价来源三态：`取自 Excel` / `已用重算结果更新` / `经人工调整`

### 8.3 顺带修掉的两个真 bug

| bug | 症状 | 成因 |
|---|---|---|
| **下载文件名被污染**（第一轮欠账） | 存出来的报告叫 `utf-8''正恒评报字[2026]第F071号.docx` | 前端正则写的是大写 `UTF-8''` 且区分大小写，而 Starlette 发的是小写 `filename*=utf-8''…`，没匹配上，前缀被当成了文件名的一部分。加 `i` 标志即修 |
| **重算出的离散度无人校验**（本轮引入） | 离散度 29% 已超 20% 阈值却不提示 | `validate()` 只在读 Excel 时查一次，查的是 Excel 里的旧值；重算后的离散度会跟着结果进报告却漏检。把 `check_dispersion(dispersion)` 按数值收参提成公开函数，`/api/compute` 返回 `提示`。**选实例正是该看见这个数的时刻** |

### 8.4 UI 重做

视觉取向**公文/档案**：纸色底、发丝栏线、印章红作唯一强调色、账簿式表格、等宽数字、步骤用大写数字壹贰叁肆伍（与报告里 `to_capital` 的大写金额同源）。

字体全部取本机已装字库（`PingFang SC`/`Microsoft YaHei` + `Songti SC`/`SimSun`），**不引任何外部资源**——本系统打包成内网单机 exe，联外网取字体既跑不通也不该跑。

顺带把原生 file 控件的英文 `Choose File`/`No file chosen` 藏掉，改用 label 代之（全中文界面里格外扎眼）；`category` 字段从可编辑文本框改为只读展示——它决定用哪份模板、列哪类实例，手改一个字（哪怕多个空格）就会在生成时炸掉，且不会重新拉实例列表。

### 8.5 仍需估价师确认的一项

**报告里要不要写明用了哪三条实例？** 这牵涉执业规范，用户、Claude 均无从验证，**本轮未做**（不做即维持金样原样，是安全的默认）。须由执业估价师定夺。

## 7. 其他未动事项

- **钉钉集成**：单独立项，须贵司合规先行（局域网机器出外网、估价数据经第三方云）
- **`copy.yaml` 打包路径 bug**：第一轮欠账。冻结包里 `Path(__file__)` 指向临时解压目录而非 exe 旁边，「改 copy.yaml 不用重新编译」的承诺打包后不成立。**打 exe 前必须补**
- **Windows exe**：PyInstaller 不支持交叉编译，须在 Windows 机器上跑一次 `uv run python build_exe.py`
- **权重**：写死各 ⅓，不可调（用户决定）。日后若开放，须一并设计其在报告中的披露方式
- **实例推荐**：不做。用户与 Claude 均无法验证可比性准则，无人能验证的推荐比没有推荐更危险
