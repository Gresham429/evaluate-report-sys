# 房地产估价报告生成系统 — 设计文档

- 日期：2026-07-15
- 状态：待评审

## 1. 目标

把估价师现有的「实勘表、比较法」Excel 工作簿，自动转成符合公司格式的 Word 估价报告。

覆盖三个类别：**农用、办公、商业**。每类一套模板。

## 2. 核心约束

这些是用户明确要求的硬约束，设计的一切取舍以它们为准。

| # | 约束 | 后果 |
|---|---|---|
| C1 | **Excel 的公式与知识是既定正确的，系统只读不改** | 系统不重算任何数值，只读 Excel 的计算缓存值 |
| C2 | **运行时零 AI 调用** | 同一份输入永远产出同一份输出；AI 仅在开发期用于反推模板 |
| C3 | **格式高度一致** | 三类报告的样板文字必须统一；已知的 25 处漂移须消除 |
| C4 | **报告文字要"稍稍灵活"** | 通过「按数据条件组句」实现，不靠模型随机性 |
| C5 | **附件是用户输入，三类都可能有，可留空** | 手动选文件 + 排序；无附件时「附 件」章节省略 |
| C6 | **留手动修改余地以供复核** | 提取结果进入可编辑的复核界面，用户确认后才渲染 |
| C7 | **Mac 开发 / Windows 运行** | 纯 Python 依赖，禁止 LibreOffice、Excel COM、poppler 等外部程序 |

## 3. 范围

**做：**
- 读取 xlsx → 提取项目数据
- 复核界面（可编辑 + 校验提示）
- 手动挑选附件、排序、PDF 转图片
- 渲染三类 docx 报告
- 本地网页应用，打包为 Windows exe

**不做（明确排除）：**
- 不重新实现比较法计算引擎（违反 C1）
- 不回写 Excel（会打破公式链，违反 C1）
- 不在运行时调用 AI（违反 C2）
- 不做多用户、不做云端、不做数据库——单机单用户，无状态

## 4. 输入约定

用户在界面上：
1. 选择 xlsx 文件（必需）
2. 选择附件文件（可选，可一个都不选），手动拖拽排序

**类别自动识别**：读实勘表 `A1` 标题（`农用地房地产实地查勘记录表` / `办公房地产实地查勘记录表` / `商业房地产实地查勘记录表`），在复核界面显示识别结果，**允许手动覆盖**。

**已知约束**：系统读的是 Excel 存储的计算缓存值。用户必须在 Excel/WPS 中**保存过**文件，缓存才是最新的。校验器会检测缓存陈旧并提示。此约束因 C7 无法规避（要实时重算就必须依赖 LibreOffice 或 Excel COM，二者都破坏跨平台）。

## 5. 架构

```
── 开发期（一次性，AI 参与）─────────────────────
   三份金样 .docx ──反推──→ templates/build.py
                              ↓
                    三份模板 templates/{农用,办公,商业}.docx
                    共享文案库 src/prose/copy.yaml

── 运行期（零 AI，纯确定性）───────────────────
   xlsx ──[extractor]──→ [model] ──┐
                                    ├──[composer]──→ [renderer]──→ 报告.docx
   附件 ──[attachments]─────────────┘         ↑
                                        templates + copy.yaml
                          [validator] ──→ 复核界面提示
```

### 组件职责

| 组件 | 职责 | 关键依赖 |
|---|---|---|
| `extractor` | 读 xlsx → 项目数据。**只读缓存值，不重算** | openpyxl |
| `model` | 项目数据模型，`@dataclass(frozen=True)` | — |
| `composer` | 按数据条件选句、填占位符 | copy.yaml |
| `attachments` | 收集用户选的文件，PDF 逐页转图，按用户排序 | PyMuPDF |
| `renderer` | 填模板出 docx | docxtpl |
| `validator` | 校验数据合理性，**只提示不阻断** | — |
| `web` | 四步向导界面 | FastAPI |

## 6. 数据流

### 6.1 字段映射

三份 Excel 的字段位置**已验证一致**，因此**只需一份映射表**：

| 单元格 | 字段 | 三份一致 |
|---|---|---|
| `A1` | 表标题（→ 类别识别） | 内容不同，位置一致 |
| `C2` | 项目名称 | ✅ |
| `C3` | 委托人 | ✅ |
| `C4` | 委托人住址 | ✅ |
| `C5` | 法定代表人或负责人 | ✅ |
| `C6` | 估价目的 | ✅ |
| `C7` | 实地勘查日期 | ✅ |
| `C8` | 价值时点 | ✅ |
| `C9` | 委托人提供的材料 | ✅ |
| `C10` | 是否取得产权证书（→ 权证条件） | ✅ |
| `C11` | 权利人 | ✅ |
| `C12` | 地址 | ✅ |
| `C13` | 设定出租用途 | ✅ |
| `C14` | 规模 | ✅（农用标签为「估价对象规模」，位置同） |
| `C15` | 估价范围 | ✅ |
| `C16` | 现使用状况 | ✅ |
| `H2` | 报告编号 | ✅ |
| `H3` | 估价作业期 | ✅ |
| `H4` | 估价报告出具日期 | ✅ |

**估价结果一览表**：表头固定在第 48 行，数据从第 49 行起，**对象数可变**（实测农用 1、办公 2、商业 2）。从第 49 行向下扫描，`F` 列序号不再是数字即停止。报告中对应表格用 `{% for %}` 循环渲染。

**比较法表**：`T39` = 评估结果单价，`X37` = 离散度。工作表名农用/商业为 `房地产比较法`、办公为 `办公房地产比较法`。

### 6.2 类别差异

| | 农用 | 办公 / 商业 |
|---|---|---|
| 面积单位 | 亩 | ㎡ |
| 单价单位 | 元/亩·年 | 元/㎡·天 |
| 年租赁价值 | `单价 × 面积` | `单价 × 面积 × 365` |
| 估价范围措辞 | 包含土地使用权 | 包含房屋及其分摊建设用地使用权 |
| 不含费用项 | 水电费、债权债务… | 水电费、网费、物业费、债权债务… |
| 「房屋安全」关注项 | 无 | 有 |

**注意**：年租赁价值的公式列于此仅为说明单位差异。**系统不执行这些计算**——`L` 列的结果 Excel 已算好，直接读取（依 C1）。

## 7. 文案库与条件组句

### 7.1 分工

- **三类通用的法定套话**（约 40 段：估价师声明、假设与限制条件、估价原则、估价依据等）→ `copy.yaml`，运行时加载，**改一处三类同步**
- **类别专属内容** → 留在各自模板 `.docx` 中，用户可在 Word 直接编辑

此折中经用户确认：日常格式与类别措辞在 Word 里改（自然），法定套话在 YAML 里改（保证三类一致，防止漂移复发）。

### 7.2 条件文本（C4 的实现）

```yaml
估价范围:
  农用: "本次估价范围包含土地使用权，不包含水电费、债权债务、特许经营权等其他权利。"
  房屋: "本次估价范围包含房屋及其分摊建设用地使用权，不包含水电费、网费、物业费、债权债务、特许经营权等其他权利。"

权证:                    # 由 C10「是否取得产权证书」驱动
  已取得: "估价对象已取得《不动产权证》"
  未取得: "估价对象未取得《不动产权证》"

资料清单:                # 同一条件联动
  已取得: "《委托评估协议书》、《不动产权证》复印件；"
  未取得: "《委托评估协议书》复印件；"

查勘人署名:              # 有名字则署名，无则省略整个从句
  有: "5.注册房地产估价师及现场查勘记录人员{{ 查勘人 }}已对本报告中的估价对象进行了实地查勘。…"
  无: "5.注册房地产估价师已对本报告中的估价对象进行了实地查勘。…"
```

灵活性来自**数据差异**而非模型随机性：同样的输入永远产出同样的句子，可复现、可审计。

**既有先例**：用户的 Excel 中已有 `H15 = IF(H6="","估价对象未取得《不动产权证》","")` 这类条件公式。系统承接既有逻辑，非新设计。

## 8. 漂移统一清单（25 处）

三份金样因人工复制粘贴，累积了 25 处措辞不一致。经用户逐条确认后统一。此表**同时是 `drift.py` 的规则来源和金样回归测试的归一化器**。

**计数口径**：按**漂移点**计，非按段落计。一个段落可能同时含漂移、项目数据与类别差异（例：「本次估价范围包含土地使用权…」一句既有类别差异「土地 vs 房屋」，又有句末标点漂移「。vs ；」），按段落计会漏。

| 漂移点 | 处数 | 现状 | 统一为 | 依据 |
|---|---|---|---|---|
| 序号点号/顿号 | **15** | 农用 `1.`（声明段）/ `1、`（原则段）；商业 `1、`/`1.` —— 三份金样自身即不自洽 | `1.` | GB/T 15834-2011 §4.5.3.5：阿拉伯数字序号后用点号；顿号仅用于汉字数字序号 |
| 冒号全半角 | 2 | 农用 `注册号：` / 办公 `注册号:` | `：` 全角 | GB/T 15834-2011：中文文本用全角冒号 |
| 方法别名 | 2 | 农用 `收益法（价值折算法）`、`假设开发法（剩余法）` / 商业 `价值折算法`、`剩余法` | `价值折算法`、`剩余法` | 三份共有段落已定名「比较法、成本法、价值折算法、剩余法四种」，后文应同名 |
| 「见诸于」 | 1 | 办公 `见诸于媒体` | `见诸媒体` | **语法错误**：「诸」=「之于」的合音，「见诸于」为冗余 |
| 「房屋安全」 | 1 | 办公 `安全、环境污染` / 商业 `房屋安全、环境污染` | `房屋安全` | 二者同为房屋类，写法应一致 |
| 缺「复印件」 | 1 | 商业附件清单第三项缺「复印件」 | 保留「复印件」 | 附件清单列的是复印件 |
| 句末标点 | 1 | 估价范围句 农用 `。` / 办公 `；` | `。` | 完整句收尾 |
| 缺书名号 | 1 | 商业 `委托评估协议书复印件` | `《委托评估协议书》复印件` | 与另两类一致 |
| 括号全半角 | 1 | 照片说明 `(1)` 半角 / `（2）` 全角，同一份内混用 | `（1）` 全角 | 中文文本用全角括号 |
| **合计** | **25** | | | |

**用户已确认**：序号统一为 `1.`（采国标，不采「1、」的行业习惯）；「见诸于」改「见诸」。

### 8.1 非漂移项（易误判，此处澄清）

以下差异**不是漂移**，须参数化而非统一：

| 类型 | 处数 | 内容 | 来源 |
|---|---|---|---|
| 项目数据 | 6 | 查勘人署名（`及现场查勘记录人员郑伟娜` 有/无）；基础设施等级（`三通一平`/`五通一平`/`六通一平`、`红线外`/`红线内外`）；权证有无（`未取得`/`已取得`，影响正文与附件清单两处）；现使用状况（`出租使用状态`/`空置`） | Excel 实勘表 `C10`、`C16`、`D27`、查勘人字段 |
| 类别差异 | 2 | `包含土地使用权` vs `包含房屋及其分摊建设用地使用权`（含不含费用项亦随之不同）；`房屋安全`关注项农用地无 | 类别 |

## 9. 附件处理

金样中「附 件」章节结构固定为六项：

```
附 件
  一、估价对象区位图
  二、估价对象照片
  三、《委托评估协议书》复印件                    ← 权证未取得
  三、《委托评估协议书》、《不动产权证》复印件      ← 权证已取得（条件）
  四、估价人员资质证书复印件
  五、估价机构资质证书复印件
  六、估价机构营业执照复印件

  估价对象区位图        ← 每块有小标题
  [图片]
  估价对象照片
  （1）（2）（3）（4）   ← 照片说明；办公类按房号标注如「（1206）」
```

第三项由 `C10` 驱动，与正文资料清单联动（同一条件，两处使用）。

**处理流程**：用户选的 PDF 用 PyMuPDF 逐页渲染为图片，按用户排序插入。图片类附件直接插入。**无附件时整个「附 件」章节省略**（C5）。

## 10. 校验

**只提示，不阻断**。是否为问题、是否修改，由估价师判断——系统无资格代为决定。

| 检查 | 依据 | 示例 |
|---|---|---|
| 比准价格离散度 | 比较法 `X37` | 5% 正常；超阈值提示复核 |
| 描述与定档矛盾 | 实勘表 D 列 vs E 列 | 「建成于2020年」vs 定档「较新(2010-2019)」 |
| 缓存值陈旧 | xlsx 修改时间 vs 计算缓存 | 改了未在 Excel 中保存 |
| 外部引用 | 公式含 `[1]` | 办公表 `I33` 指向 `/Users/admin/Desktop/…` 绝对路径 |
| 一览表自洽 | `L ≟ J × K × (365)` | 手工改单价未重算 |
| 必填字段缺失 | `C2`–`C16`、`H2` | 报告编号为空 |

以上每一项均源自真实排查中遇到的问题，非假想。

办公类另有 `案例素材/办公/附件/` 三份 PDF（海创703、海创808、租赁合同），用于验证附件流程。

**归一化比对**：因漂移已被有意统一，输出不会与金样逐字相同。测试将金样也过一遍 `drift.py` 规则后再比对，断言「除已确认的 25 处改进外，其余一字不差」。

- `extractor`：给定 xlsx 单元格 → 期望字段值

## 14. 交付形态

```
估价报告系统/
├── 估价报告系统.exe      ← 双击，自动开浏览器
├── templates/            ← 外置，用户可在 Word 编辑
│   ├── 农用.docx
│   ├── 办公.docx
│   └── 商业.docx
└── copy.yaml             ← 外置，用户可编辑
```

模板与 `copy.yaml` 外置、不打进 exe，用户改措辞无需重新编译。

**交互流程**：

```
① 选 Excel  →  ② 复核数据（可编辑 + 校验提示）  →  ③ 挑附件、排序  →  ④ 生成下载
```

第②步的修改**仅影响本次报告，不回写 Excel**（依 C1：回写会打破公式链，把计算结果变成死数）。发现数据有误的正确做法是回 Excel 修改、保存、重新导入。

## 15. 已知约束与风险
