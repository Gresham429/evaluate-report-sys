## 0. 现状（先说清楚有什么、没什么）

- **有：报告编号（report_no）自动领号。** `src/dingtalk/report_number.py::draw_report_number` 向台账多维表
  的 autoNumber 字段『报告序号』要一个**全公司唯一递增**号，拼成 `正恒评报字[2026]第N号`；**出报告时在线领**
  （离线则存「待同步」，联网补领）。这是**报告**的编号，不是实勘的。
- **无：实勘编号。** 一份实勘问卷目前只有 `问卷ID`（uuid 前 12 位十六进制，内部标识、非人类可读、非递增）。
  **没有**「实勘编号」这种面向人的、可领取、可递增的编号。

## 1. 这个功能是什么（待甲方确认后细化）

给每份**实勘问卷**一个人类可读、公司内唯一、递增的**实勘编号**（区别于 `问卷ID` 与 `报告编号`）。
自动领取 + 递增，估价师现场填时/提交时得到一个正式编号。

## 2. 待甲方拍板的问题（决定怎么实现）

1. **编号格式**：前缀？年份？流水号位数？例如 `正恒实勘[2026]第N号`？还是别的规则？
2. **领取时机**：现场**新建问卷时**领，还是**提交时**领？（影响离线：现场大概率无网 → 可能要离线占号或提交时领）
3. **递增范围/重置**：全公司唯一？按年重置流水？按类别分段？
4. **谁领**：小程序端（现场估价师）领，还是办公端领？跨设备并发怎么保证不重号？
5. **与报告编号的关系**：实勘编号 → 出报告时映射成报告编号？还是两套独立编号并存？
6. **离线**：现场断网时能不能先给个临时/占位号、联网再定？（同报告编号的「待同步领号」思路）
7. **可否修改/作废**：领错了能不能改？作废号回收还是留空？

## 3. 将来落地时的接入点（技术预研，非承诺）

- **复用报告编号那套**：多维表 autoNumber 字段是现成的「全公司唯一递增」机制——可为实勘问卷表加一个
  autoNumber 字段『实勘序号』，`draw_report_number` 的模式（读回自动号 → 拼编号）可平移出一个
  `draw_survey_number`。**全公司唯一**须由中心（多维表）发号，单机/离线做不了真唯一（同报告编号的结论）。
- **落到问卷行**：作为一列（如 `实勘编号`，与 `问卷ID`/`共有人` 平铺），两侧记录契约（record.py + backend.py）同步。
- **领取路径**：若小程序端领 → 经 broker 向多维表领（须 broker 加动作 + 重部署）；若办公端领 → 办公端直连多维表领。
- **离线**：参照报告编号的「离线存待同步、联网补领」；或现场先占本地临时号、提交时换正式号。
