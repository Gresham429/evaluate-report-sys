## 0. 一句话

app 默认联网、直连多维表出正式报告；断网时照常填表，但填完点"出报告"会存成**「待同步」草稿**并打标；
联网后在草稿列表逐条**对账**——**同步**（领号 + 出正式报告 + 写多维表台账）或**删除**，**不留悬空的未同步件**。

## 1. 范围

**做（本轮）：**
- **app 联网默认**：启动读 `.env`、开 `承载后端=多维表`，三个 Store 走 Notable 后端（多维表为权威）。
- **报告编号统一发号**：出正式报告时从多维表 autoNumber 领号，替代现在的"估价师在表单里手填号"。
- **离线出报告 → 待同步草稿**：断网点"出报告"→ 存成 `待同步` 草稿（不领号、不出报告、不落台账）。
- **联网对账界面**：草稿列表里待同步草稿醒目标注 + 每条 [同步定稿] / [删除]。
- **在线检测**：on-demand（点"出报告"实测一次）+ **手动刷新**按钮；不后台轮询（决策 3）。

**不做（各自独立、明确延后）：** 钉钉登录鉴权 + 按人裁剪缓存（§7b，须先单独设计）；成品 docx 归档钉盘（§3⑥，须钉盘 scope）；
实例/基础表的离线待同步（用户选最小范围＝**只报告草稿**，实例/基础表仍只在线加）。

## 2. 三个已定决策（与用户逐条敲定）

1. **报告编号：估价师手填 → 多维表统一发号。** 出正式报告时 `draw_report_number()` 从台账表 autoNumber 领全公司唯一递增号，
   组装 `正恒评报字[YYYY]第N号`。这是产品改动（估价师不再自己编号），用户已拍板。
2. **不同步的删掉：对账界面手动点删，不静默自动删**（防误丢）；待同步草稿在列表里一直醒目提示，直到被同步或被删。
3. **在线检测：on-demand + 手动刷新。** 点"出报告"那一刻实测一次；再给一个"刷新在线状态"按钮让用户主动重测。不后台常驻轮询。

## 3. 三态流程

```
              点“出报告”
                  │
        ┌──── 在线? (/api/online 实测) ────┐
       是                                  否
        │                                  │
  领号(autoNumber) → render docx      存成 Draft(待同步=True)
   → 写台账(多维表) → 返回 docx         → 提示“已存待同步草稿，联网后定稿”
        │                                  │
     正式报告                        草稿列表里带「待同步」徽标
                                           │
                                   联网后对账（逐条）
                                    ├─ [同步定稿] → 走在线出报告流程 → 成功后删掉该草稿
                                    └─ [删除]     → 丢弃该草稿
```

## 4. 数据模型改动

`Draft`（`src/drafts/model.py`）加一个字段 **`待同步: bool`（默认 False）**：

- 普通草稿（在线边填边存、还没出报告）：`待同步=False`。
- 离线完成、点"出报告"落下的：`待同步=True`，`报告编号` 留空（领号在同步时才发生）。

`DraftStore.to_dict/from_dict` 随之读写该字段；缺省视为 False（老草稿兼容）。**不校验 `数据` 形状**（沿用现状）。

## 5. 在线检测（新端点 + 手动刷新）

- 新端点 **`GET /api/online`**：`承载后端≠多维表` → 直接 `{online: false}`（本地模式无多维表）；否则用 `NotableClient` 做一次轻量探测
  （`list_sheets()` 或一次 `maxResults=1` 的 list），成功=在线、抛错/超时=离线。
- 前端在**点"出报告"时**先调它决定走哪支；**"刷新在线状态"按钮**再调一次、更新界面标识。
- 超时要短（如 5s），免得离线时"出报告"卡很久。

## 6. 报告编号发号 + `/api/render` 改动

在线出报告：`/api/render` 在 render 之前先 `draw_report_number(client, 台账表, year)` 拿号 → 注入项目的 `报告编号` → render → 台账写多维表。

**【实现细节，实施计划里对着代码定】** 领号↔台账的行模型：autoNumber 在"插入一行"时才生成，而 `报告编号` 又要在 render 前拿到——
候选做法：领号即插一条台账行拿到 N、`报告编号=format(N)`、render 用它、该行的 `快照` 存本次报告的自洽快照（`报告编号` 由 autoNumber 派生或回填进快照）。
须对着现有 `LedgerEntry`/`replay.py` 的契约把"报告编号 派生 vs 存进快照"定死，保证 replay 仍自洽（铁律 #5）。**本 spec 不锁死实现，交实施计划。**

## 7. 离线分支

点"出报告"时 `/api/online=false`：**不 render、不领号、不落台账**，把当前表单存成 `Draft(待同步=True, 报告编号="")`，
返回提示"当前离线，已存为待同步草稿，联网后到草稿列表定稿"。数据全在草稿里，够日后一键定稿。

## 8. 对账界面（前端 `web/static/index.html`，单文件原生 JS）

- 草稿列表：`待同步` 草稿加**醒目徽标**（如"⏳待同步"）+ 顶部"刷新在线状态"按钮 + 当前在线/离线小标识。
- 每条待同步草稿两个操作：
  - **[同步定稿]**：仅在线可点（离线置灰）→ 载入该草稿数据走出报告流程（领号 + render + 台账）→ **成功后删掉该草稿**（它已成正式报告）。
  - **[删除]**：丢弃该待同步草稿（决策 2：手动删）。
- 收口沿用现有 `openForm()` 末尾 `loadDraftList()`（§5 坑 2：状态切换后刷新列表）。

## 9. 铁律与边界

- **领号 / 出正式报告需联网**（§3①）；离线只出待同步草稿——与"数据留公司钉钉 + 本地缓存"一路。
- **快照自洽(#5) / 运行时零 AI(#3) / 台账只增不改(#4)** 全保留：领号/在线检测都不是"报告生成阶段的模型调用"；同步仍是 append。
- **前端单文件改动 → 铁律：改 UI 必须真机点**（§5 坑 2/4，四轮评审都在这栽过）。实现后须真人走一遍：离线出报告→存待同步→联网刷新→同步/删除。
- 报告编号从手填改发号是产品改动，已用户拍板（§2-1）；老报告的历史编号不受影响（只影响此后新出的报告）。
