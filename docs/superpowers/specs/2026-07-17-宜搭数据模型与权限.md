# 设计：宜搭数据模型 + 权限映射（钉钉承载层落地）

- 日期：2026-07-17
- 关联：`2026-07-17-钉钉全公司同步-design.md`（§2b 定承载层=宜搭）。本文把"宜搭里到底建几张表、什么字段、权限怎么配"钉具体。
- 定位：给在宜搭里搭表/配权限的人（你 + IT）用；末尾 §6 是**只有你能在宜搭里核实的清单**。
- 仅设计，未写代码。本地侧的"宜搭适配器"等本文核实通过后再写。

## 1. 总原则

1. **一张宜搭表镜像一类 Store 数据**：台账、实例库、基础表版本各一张（草稿不上云，见 §5）。
2. **快照是权威，索引字段是冗余**：台账/基础表把"整份自洽快照 JSON"存进一个大字段（权威）；
   另把编号/时点/结果/类别/归属等**从快照里冗余出几列**，纯为宜搭的列表、筛选、权限用。算术仍以快照为准。
3. **append-only 靠权限强制**（铁律 #4）：台账/基础表版本表，普通角色**只给"新增"、不给"编辑/删除"**权限。
   改不了的记录才构成依据——这条在宜搭侧由权限保证，不靠客户端自觉。
4. **产物 docx 走附件字段**；估价师现场照片只在 docx 里，故必须存 docx（决定⑥）。
5. **报告编号 = 宜搭流水号**：领号时创建一行、拿自增流水号，app 按它格式化成"正恒评报字[年]第 F×× 号"。

## 2. 表设计（4 张表 + 草稿留本地）

### 表 A「报告」（领号 + 产物 + 归属锚点）—— 一份报告一行
实勘开始时创建（决定①：手机领号），是权限与产物的锚。

| 字段 | 宜搭类型 | 说明 |
|---|---|---|
| 报告编号 | **流水号** | 全公司唯一递增；app 取值格式化成法定编号。**这就是编号服务。** |
| 类别 | 单选 | 农用/办公/商业/住宅/工业/停车场用地/建设用地 |
| 归属人 | 成员 | = 创建人（owner）。权限按它裁剪 |
| 归属组 | 部门 | owner 所在小组。组内 2-3 人共享 |
| 状态 | 单选 | 在办 / 已出正式报告 |
| 领号时间 | 日期 | |
| 估价报告 | 附件 | 成品 docx（含照片） |
| 委托评估协议书 | 附件 | 成品 docx |

### 表 B「台账」（append-only 快照）—— 一次生成一行，可多行
铁律：同一编号生成 N 次就是 N 条。引用表 A 的报告编号。

| 字段 | 宜搭类型 | 说明 |
|---|---|---|
| 记录号 | 单行文本 | 唯一（app 生成，uuid 前 12 位） |
| 报告编号 | 单行文本/关联 | 指向表 A |
| 类别 | 单选 | 冗余，便于筛选 |
| 生成时间 | 日期 | |
| 经手人 | 成员 | |
| 结果单价 | 数字 | 冗余（比准评估结果），便于列表看 |
| 离散度 | 数字 | 冗余 |
| 归属人 / 归属组 | 成员 / 部门 | 冗余自表 A，供权限 |
| **快照** | **多行文本**（已验证） | 整份自洽 `LedgerEntry` JSON（基础表实际知识/实例/方法/权重/资产状况/偏离/结果全在内）。样例 12KB 可入多行文本字段（2026-07-18 用户实测），不用附件 |

### 表 C「实例库」—— 一实例一行（自由贡献 + 留痕，决定④）

| 字段 | 宜搭类型 | 说明 |
|---|---|---|
| 编号 | 单行文本 | 唯一 |
| 类别 | 单选 | |
| 位置 / 出租用途 / 交易情况 / 租期原文 / 备注 | 单/多行文本 | |
| 成交价 / 面积 / 交易情况指数 | 数字 | |
| 起始日 | 日期 | |
| 日期精度 | 单选 | 年月日 / 仅年月 等 |
| 因素档次 | 多行文本 | 28 因素→档次 的 JSON（够小，文本字段即可） |
| 贡献人 / 贡献时间 | 成员 / 日期 | 留痕 |

### 表 D「基础表版本」—— 一版一行（中心发布，决定③；旧版永不覆盖，铁律 #8）
现有的 `基础表/台账.json` 索引在宜搭里**收敛成这张表本身**（一版一行，按类别查、按导入时间排）。

| 字段 | 宜搭类型 | 说明 |
|---|---|---|
| 类别 | 单选 | |
| 指纹 | 单行文本 | 版本号（内容哈希）。(类别,指纹) 唯一 |
| 导入时间 / 来源文件名 / 导入人 | 日期/文本/成员 | |
| 知识 | 多行文本 | `Knowledge` 的 to_dict JSON（分值标尺 + 28 因素[行号/名称/档次/系数/分组/调整范围]） |

## 3. 权限映射（钉钉组织 → 宜搭数据权限）

- **角色（源真 = 钉钉组织）**：普通估价师、总估价师、知识管理员。宜搭角色/权限组对接钉钉部门/角色，离职入职自动跟随（§7b）。
- **表 A/B（报告/台账）数据权限**：
  - 普通估价师：可见 `归属人=自己 OR 归属组∈自己部门` 的行；**新增可，编辑/删除禁**（append-only）。
  - 总估价师：**全部可见**（final 审阅）；仍禁改历史台账。
- **表 C（实例库）**：全员可**新增**（自由贡献）；可见全部（公司共享资产）；编辑/删除禁或仅管理员。
- **表 D（基础表版本）**：**仅知识管理员可新增**（中心发布）；全员只读；无人可编辑/删除（旧版永不覆盖）。
- **本地缓存按人裁剪**（§7b 安全红线）：app 只拉当前登录用户"数据权限内"的行，本地缓存天然只含其可见部分。

## 4. 对本地代码的影响（印证之前的判断）

- **台账**：宜搭适配器 = `LedgerBackend` 的宜搭实现（append=表 B 新增一行、iter=查表 B）。**第一刀的内存后端就是它的契约**，已就绪。
- **基础表**：适配器 = 表 D 新增一行（发布）/ 按(类别,指纹)查。缝口干净，是下一刀 `BaseTableBackend` 的形状。
- **实例库**：适配器 = 表 C 增行/查行。**这印证了 InstanceStore 该从"整档 load/save"改成"一条一行"** —— 故 InstanceStore 的后端抽象要等本设计定稿再做（否则按整档抽会返工）。
- **报告/编号**：新增"领号"调用（表 A 建行取流水号）+ 产物上传（表 A 附件）。

## 5. 草稿（DraftStore）不上云

草稿是"填一半别丢"的个人临时件、非公司资产（决定 §7b 倾向）。**留本地**，DraftStore 不做宜搭后端。
好处：个人隐私、离线随便填、不占宜搭额度。将来若要"换机续填"再议。

## 6. 宜搭内核实清单（**2026-07-18：用户在本地钉钉/宜搭实测，7 条均可行**）

> 状态：已验证通过。快照 12KB 可入多行文本字段（第 1 条），流水号/附件/权限/OpenAPI/组织均可行。
> 表结构据此定稿；下一步转入"建表 + 写宜搭适配器"。原清单留档如下。

按重要性排，**第 1 条最关键，先验**：

1. **大文本字段能否装下整份台账快照**：建张表、一个多行文本字段，塞一份真实 `LedgerEntry` 快照 JSON
   （可能几十 KB）。存得下 → 用文本字段；**存不下/被截断 → 快照改用「附件」字段**（上传 .json 文件），
   表 B 行里只留索引列 + 附件。这决定表 B 的"快照"字段类型。
2. **流水号字段**：宜搭有无自增流水号？能否保证全公司唯一递增、能否设起始值/前缀。用作报告编号。
3. **数据权限表达力**：能否配出"归属人=当前用户 OR 归属组∈用户部门；某角色全看"。配不出则权限模型要调。
4. **能否禁编辑/删除**：普通角色能否只给"新增"、锁死"编辑/删除"（append-only 靠这个）。
5. **OpenAPI**：能否程序化 增行 / 查行(分页) / 传下附件；**限流额度**多少（首次全量拉基础表/实例要分批）。
6. **附件字段**：能存 docx、大小上限、能否程序化上传下载。
7. **组织对接**：app 能否读到宜搭/钉钉的成员/部门/角色（做身份 + 权限），离职入职是否自动反映。
