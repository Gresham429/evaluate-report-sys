## 2. 本特性范围

**做（#3+）：**
- A. 审核定稿**状态机**：`草稿 → 已提交 →(办公端出报告+发起审核)→ 待审核 →(审核通过)→ 已定稿(锁定)`。
- B. 办公端**钉钉扫码登录** + 身份识别。
- C. 权限**「只看自己」**（办公端按登录 userid 过滤）。
- D. **批量**发起审核 / 批量审核通过。
- E. 小程序：状态=已定稿 → **整份只读**。

**明确延后（占位，用户后续给组织架构再补）：**
- **部门领导审核**：本期「审核通过」动作**不做角色鉴权**——谁登录谁能点（占位）；引入组织架构后，把「审核通过/定稿」限制为部门领导，并让领导能看下属的。
- 驳回/退回流程（待审核→打回可改）：本期可选，最简可先只做「通过」。

## 3. 状态机与多维表状态字段

**生命周期（单一 `状态` 字段，扩两个值）：**

```
草稿 --小程序提交--> 已提交 --办公端「出报告+发起审核」(可批量)--> 待审核
   待审核 --「审核通过」(可批量;现占位不鉴权,后续限部门领导)--> 已定稿(终态·锁定)
   待审核 --「驳回」(可选,后续)--> 已提交
```

- `状态` 现值：`草稿 / 已提交`；**新增 `待审核 / 已定稿`**。记录契约在**两处**：`serverless/survey_broker/record.py`（vendored）与 `src/questionnaire/model.py`/`backend.py`——**改状态常量要两侧同步**，`tests/test_survey_broker_record.py` 契约测试会拦漂移。
- 办公端拉取过滤调整：
  - 「从实勘问卷拉取」出报告：拉 **已提交**（未审核的）——同现状。
  - 审核列表：拉 **待审核**。
  - 已定稿：单独可查/归档，不再出现在「待出报告」里。
- 小程序 `_toRows`/`reconcileFromServer`：`已提交|待审核|已定稿` 均算 submitted（进「已提交」分组，标签显示各自状态）；`已定稿` 触发只读。

## 4. 办公端钉钉扫码登录 + 身份

办公端＝本机桌面 exe（`src/web/app.py` 后端 + `src/web/static/index.html` 单文件前端，本地端口）。现**无登录**。加：

- **钉钉扫码登录（OAuth2 授权码）**：前端展示登录入口 → 拉起钉钉扫码 → 拿 `authCode` → 后端用**同一新应用**的 Client ID/Secret 换 userid（复用 broker `identity.py` 的换 userid 思路，或调 `getuserinfo`）。
- **回调/端口**：本机应用，redirect 用 `http://localhost:<端口>/auth/callback`，须在钉钉后台**登录相关的 redirect 白名单**登记。**# 待真机校准**：钉钉网页/扫码登录的具体端点、redirect 配置、authCode 换 userid 的接口，按文档假定 + 部署校准。
- **会话**：登录后把 userid 存进办公端会话（内存/本地），后续所有拉取带上它。
- **不改单机纯本地模式**：未配多维表/未登录时的本地出报告流程保持（登录只在多维表承载模式下要求）。

> 备选（若扫码登录一时打不通）：先用**手工填 userid / 从 .env 读操作人**做过渡，把「按 userid 过滤」的链路先跑通，登录 UI 后补。设计上把「取当前 userid」抽成一个函数，登录方式可替换。

## 5. 权限「只看自己」

- 办公端 `SurveyPullBackend`（`src/questionnaire/backend.py`）+ `/api/survey/list`（`src/web/app.py:928`）加 **filler 过滤**：只列 `填报人==当前登录 userid` 的问卷。
- 审核列表、批量操作范围同样限当前 userid。
- **部门领导看下属**：占位——引入组织架构后，按登录人角色/部门放开可见范围（本期不做）。
- 与小程序 #2 对称：小程序端已「只看自己」（`listSurveys(filler)`）；办公端本期补齐同一约束。

## 6. 批量操作

- 办公端审核/列表页支持多选：
  - 批量**发起审核**：选中若干 `已提交` → 状态改 `待审核`。
  - 批量**审核通过**：选中若干 `待审核` → 状态改 `已定稿`。
- 后端：`NotableClient.update_record` 逐条改状态（可加一个 `update_status(sheet, record_id, status)` 薄封装或复用现有）；提供批量端点 `/api/survey/review`、`/api/survey/finalize`（body 带 survey_id 列表）。**已定稿是否可再改**：本期定为终态、办公端也不再改（若要「解锁」留后续）。
- 与铁律 #4（台账只增不改）不冲突：改的是**实勘问卷表**（可变），非台账。

## 7. 小程序：已定稿只读

- `pages/form/form.js`：`_refreshFromServer`/`resume` 拿到 `status==='已定稿'` → 设 `readonly=true`。
- `form.axml`：`readonly` 时——输入框 `disabled`、隐藏「暂存/提交/现场采集/逐因素」入口或置灰，顶部显「✓ 已定稿·不可修改」。逐因素页/采集页同理只读（或不让进）。
- `待审核` 是否可改：建议**待审核也只读**（已进入审核流程不该再动），仅 `草稿/已提交/驳回` 可改。最终以用户口径为准（新会话确认）。

### 真机测试发现并修（2026-08-12）

- **办公端身份必须用 userid，不能挪用 `NOTABLE_OPERATOR_ID`**：后者是多维表 API 的 operatorId，取
  **unionId**（`jYDA…`）；而问卷「填报人」来自小程序免登，是 **userid**（如 `10076`）。原过渡取值用
  `NOTABLE_OPERATOR_ID` 去过滤填报人，一条都匹配不上（真机实测 4 行问卷全被挡）。**已修**：办公端身份
  单列 `OFFICE_OPERATOR_ID`（userid，`config.office_operator()`）；步骤 6 钉钉扫码登录返回的也是 userid，无缝替换。
- **可见范围改「分角色」（用户 2026-08-12 定）**：不是纯「只看自己」——普通估价师只看自己，**管理员看全部**

  `OFFICE_ADMINS`（userid 名单，`config.office_admins()`）+ `session.visibility_filter()`（空="fail-closed / 管理员=None看全部 / 普通=本人)；
  `/api/me` 加 `is_admin`；出报告/审核/拉取/批量全走 `visibility_filter()`。前端审核页操作人处显示「管理员·查看全部 / 只看自己」。
