# 设计：智能实勘问卷 · 钉钉小程序前端 v1（现场采集）

- 日期：2026-07-19
- 状态：与用户（建设方）敲定范围（brainstorming 通过）；**仅设计**。
- 承接：`docs/superpowers/specs/2026-07-19-智能实勘问卷-design.md`（总设计）、`serverless/survey_broker/`（已上线验通的 broker）、`src/questionnaire/`（办公端拉取）。

## 0. 一句话
钉钉原生小程序，估价师现场手机填 **19 项基本信息 + 地图预填地理事实**，免登记填报人，暂存/跨设备续填/提交 → 进多维表「实勘问卷」表 → 办公端（现成）拉「已提交」预填出报告。

## 1. 范围

**v1 做（本设计，零基础表依赖）：**
- 免登拿身份（`dd.getAuthCode` → broker 新增 `whoami` 换 userid = 填报人）。
- 基本信息 19 项表单（对齐 `src/extractor/field_map.py::SURVEY_FIELDS` 的键）。
- 地图预填：取 GPS → broker `prefillGeo` → 显示地址/附近公交/最近地铁/周边配套（**只显示事实供参考**，不做档次）。
- 暂存（`saveDraft` 状态=草稿）+ 跨设备续填（「我的草稿」列表 → `loadDraft`）+ 提交（`submit` 状态=已提交）。

**v1 不做（明确延后 v2，理由：共享「基础表因素表」依赖）：**
- **28 因素档次下拉** 与 **资产状况逐因素描述**——两者都要基础表的因素名列表（办公端靠因素名归组，名字对不上落不进报告）。v2 先把基础表导入多维表 + broker 加 `factors(category)` 端点（读 `基础表` sheet，即 `NotableBaseTableBackend`），再做这两块。
- **照片**——存储方式未定（钉盘/OSS/多维表附件字段，见总设计 §4.1 待验），v2 决策后做。

## 2. 架构与数据流

```
钉钉小程序（手机）
  onLoad: dd.getAuthCode → POST broker {action:whoami, payload:{authCode}} → {userid, name}=填报人
  表单页: 填 19 基本信息；点「地图预填」→ dd.getLocation → POST {action:prefillGeo,{lng,lat}} → 显示事实
  暂存: POST {action:saveDraft, payload:{survey_id?, filler, category, updated_at, content}} → {survey_id}
  续填: 入口列草稿(按 filler 过滤，见 §5) → POST {action:loadDraft,{survey_id}} → 回填表单
  提交: POST {action:submit,{survey_id}}
        ↓（一切经 broker，前端不持任何密钥）
serverless broker（阿里云 FC，已上线）→ 钉钉多维表「实勘问卷」表
        ↓
办公桌面端（现成）直读「已提交」→ survey_to_prefill → 预填出报告
```

- content 形状（与办公端 `_fields_to_response` / broker `record.py` 对齐）：
  `{basic:{<19 键>}, gps:{lat,lng}, subjects:[], subject_levels:{}, asset_conditions:{}, photos:[]}`
  —— v1 只填 `basic` 与 `gps`，其余四项留空（办公端预填对空值已优雅处理，`src/questionnaire` 全测覆盖）。
- `category` 由估价师在表单顶部下拉选（农用/办公/商业/住宅/工业/停车场用地/建设用地，取自 `Category` 枚举值）。

## 3. broker 改动（唯一新增）

新增 action **`whoami`**：payload `{authCode}` → `{userid, name}`。
- 用现有 `DINGTALK_APP_KEY/SECRET`（即多维表那套应用凭据，同一企业内部应用）调钉钉免登接口把 authCode 换成 userid（+ 可选姓名）。
- **钉钉免登具体接口待真机校准**（同现有三处校准法）：候选 `POST /topapi/v2/user/getuserinfo`（旧）或 `/v1.0/contact/users/...`。实现按文档假定 + `# 待真机校准` 注释，部署后打一次真机核实。
- 失败（authCode 无效/接口错）→ 返回 4xx JSON，不崩（沿用 server.py 边界兜底）。
- **鉴权说明**：v1 `whoami` 只用于取填报人身份，**暂不强制**每个写操作带 authCode（触发器仍 anonymous）。上线前的 authCode 强制鉴权是独立的一步（见总待办），不在本 v1。

## 4. 组件（钉钉原生小程序）

```
miniprogram/                      # 钉钉小程序根（用钉钉开发者工具打开、上传）
├── app.js / app.json / app.acss  # 全局：broker BASE_URL 常量、页面注册、全局样式
├── utils/broker.js               # 封装 POST broker（dd.httpRequest，统一 {action,payload}→JSON）
├── pages/index/                  # 入口：免登 + 我的草稿列表 + 新建
│   ├── index.axml/.acss/.js/.json
└── pages/form/                   # 表单：基本信息 + 地图预填 + 暂存/提交
    ├── form.axml/.acss/.js/.json
```

- `utils/broker.js`：`request(action, payload) -> Promise<obj>`，`BASE_URL` 指向 FC 域名；错误统一抛。
- `pages/index`：`onShow` 免登拿 filler；列「我的草稿」（§5 过滤）；点草稿→带 survey_id 进表单续填；「新建」→空表单。
- `pages/form`：19 字段受控输入 + 类别下拉；「地图预填」按钮→`dd.getLocation`→`prefillGeo`→展示事实块；「暂存」「提交」按钮。

## 5. 草稿列表怎么过滤（关键细节）

broker `loadDraft` 按 survey_id 取单份；**没有「列我的草稿」接口**。v1 两种做法二选一（实施计划定）：
- **A（推荐，v1 够用）**：小程序**本地 `dd.setStorage`** 记「我在本机存过的 survey_id 列表」，入口据此逐个 `loadDraft` 拉摘要。跨设备续填靠估价师**手动记 survey_id**或扫码——v1 先本机续填，跨设备 v2 再加 broker「按 filler 列草稿」端点。
- **B**：broker 加 `listDrafts(filler)` 端点（读全表按 filler+状态=草稿过滤）。更好但多一个端点。
> 默认 A（更少 broker 改动）；跨设备续填标为 v2。
