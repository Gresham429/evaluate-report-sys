## 0. 一句话

让估价师现场填写「不丢数据、秒开、可离线续填」：表单每次改动即本地自动存盘；入口页从本地缓存秒出草稿列表并后台对账；提交成功后清本地内容缓存并自动退回入口页（自动退出已在 v1 完成，本版收尾）。

## 1. 问题（v1 现状复盘）

v1 唯一的本地存储是 `myDrafts`＝一串 `survey_id`。草稿**内容**只在服务端（broker→多维表）。由此三个现场痛点：

1. **改动不落盘**：填到一半切后台/被杀/断网，未点「暂存」前所有输入丢失。现场信号差时这是必然事故。
2. **入口页每次 N 次网络往返**：`onShow` 对每个 `survey_id` 都 `loadDraft` 拉摘要；慢，且离线＝空列表。
3. **续填依赖网络**：`resume` 走服务端 `loadDraft`；刚在本机填的草稿离线打不开。

## 2. 目标与非目标

**目标（P0，本版做）**
- G1 **改动即存**：表单任一字段/类别/GPS 改动，立即把整份内容写入本地缓存（keyed by 草稿）。切后台/重启/断网都能恢复到最后一次改动。
- G2 **入口秒开且离线可用**：入口页先用本地索引即时渲染列表，再后台向服务端对账刷新；离线时仍显示本地已知草稿。
- G3 **续填先读本地**：`resume` 优先本地内容缓存即时回填，联网时后台用服务端版本对账。
- G4 **提交收尾**：提交成功→清该草稿的重内容缓存（索引保留一条「已提交」轻记录）→自动退回入口页（沿用 v1 的 `setTimeout→navigateBack`）。

**非目标（延后，避免范围蔓延）**
- 不做真正的「离线提交队列」（无网也能 submit 后自动补传）。本版：无网时**暂存到本地不丢**，联网后**手动重试**暂存/提交即可。理由：自动补传要 broker 幂等契约+冲突解决，属独立一章，且真机不可测。
- 不做跨设备续填（v1 已明确 v2）。
- 不动 28 档次/逐因素/照片（v2）。

## 3. 数据模型（本地 `dd.setStorage`）

两类键，全部 JSON：

| 键 | 形状 | 用途 |
|---|---|---|
| `draftIndex` | `[{ id, serverId, category, status, updatedAt, dirty, submitted }]` | 入口页列表数据源（轻量，可离线渲染） |
| `draft:<id>` | `{ id, serverId, category, basic:{...}, gps, geo, updatedAt, status, dirty }` | 单份草稿完整内容（续填/恢复用） |

- `id`：客户端本地 id。新建草稿即刻生成 `local-<ts>-<rand>`，作为**创建到首次服务端存盘之间**的稳定 key。
- `serverId`：服务端 `survey_id`。首次 `saveDraft` 成功后回填，并把 `draft:<localId>` 迁移/关联到 serverId、更新索引里那条。
- `dirty`：本地有改动、尚未成功同步到服务端。
- `submitted`：已提交（索引保留但内容缓存可清）。

**server 仍是 ID 与同步权威**：本地 id 只在「还没拿到 serverId」的窗口用；一旦有 serverId，以 serverId 为准对账。

## 4. 组件

新增 `miniprogram/utils/store.js`（纯逻辑 + `dd.*` 存储的 Promise 薄封装，便于 Node 打桩单测）：

```
getStorage(key) / setStorage(key,val) / removeStorage(key)   // Promise 化 dd.*，缺省返回 null
readIndex() / writeIndex(list)                                // draftIndex 读写
upsertIndexEntry(entry)                                       // 按 id/serverId 合并一条（去重）
saveDraftLocal(draft)                                         // 写 draft:<id> + upsert 索引，回 draft
loadDraftLocal(id)                                            // 读 draft:<id>（含按 serverId 回退查找）
clearDraftContent(id)                                         // 删 draft:<id>，索引置 submitted=true 保留
attachServerId(localId, serverId)                             // 首存成功后关联并对账索引
reconcileFromServer(rows)                                     // 服务端摘要合并进本地索引（联网对账）
newLocalId()                                                  // local-<ts>-<rand>
```

改 `pages/form/form.js`：
- `onLoad`：有 `draftId`→`resume`；否则 `newLocalId()` 建空本地草稿。
- `onField/onCategory/onGeo`：`setData` 后调 `_autosave()`（写 `draft:<id>`、标 `dirty`、更新索引 `updatedAt`）。
- `resume(id)`：先 `loadDraftLocal` 即时回填；联网再 `loadDraft` 对账（服务端较新且本地非 dirty 时覆盖）。
- `onSave`：`saveDraft`→成功则 `attachServerId`＋标 synced（`dirty=false, status=草稿`）；失败则内容已在本地、标 `未同步` 提示重试（不丢）。
- `onSubmit`：`saveDraft`→`submit`→成功则 `clearDraftContent`＋索引标 `已提交`＋toast＋`setTimeout→navigateBack`（沿用）；失败保留本地内容+提示。

改 `pages/index/index.js`：
- `onShow`：先 `readIndex()` 即时 `setData` 渲染；再（联网）对已知 serverId 批量/逐个 `loadDraft` 刷新状态→`reconcileFromServer`→回写索引+`setData`。离线则止于本地渲染。

改 `pages/form/form.axml` / `index.axml`：增「● 本地未同步/离线」轻标记（复用现有 `dirty`/`synced`/`muted` 样式，最小改动）。

## 5. 关键流程

**新建→填→切后台→重开**：进表单即建 `local-*`；每次输入 `_autosave`。切后台/杀进程，`draft:<id>` 与索引都在。重开入口页→本地索引列出该草稿（标未同步）→点开 `resume` 从 `draft:<id>` 秒恢复。**零丢失。**

**暂存联网**：`saveDraft` 回 `survey_id`→`attachServerId(localId, serverId)`→索引那条 `serverId` 回填、`dirty=false, status=草稿`。

**暂存断网**：`saveDraft` reject→内容早已本地落盘→只更新提示「未同步，联网后重试」，`dirty` 保持 true。用户联网后再点暂存即补传。

**提交**：`saveDraft`（拿/更 serverId）→`submit`→成功 `clearDraftContent(id)`（删重内容，索引留 `submitted=true, status=已提交`）→toast→1.2s 后 `navigateBack`/`reLaunch`。入口页 `onShow` 本地索引即显示「已提交」。

## 6. 一致性与边界

- **本地/服务端冲突**：仅当「服务端 `updated_at` 更新 且 本地 `dirty=false`」才用服务端覆盖本地；本地有未同步改动时**不覆盖**（护住现场输入）。
- **索引去重**：`upsertIndexEntry` 优先按 `serverId` 匹配，其次 `id`；避免 local→server 迁移后出现两条。
- **存储失败**：`dd.setStorage` 失败仅记日志不阻断填写（内存 `data` 仍在，用户可继续点暂存走服务端）。
- **提交后再进同 survey**：索引 `submitted=true`；`resume` 若本地无内容则回退服务端 `loadDraft`（已提交件仍可只读查看）。

## 7. 铁律处置

- #1 金样 / #3 运行时零 AI：仍只采集、不算术；缓存是本地存储优化，不触碰计算/金样。
